## 4. MemoryObservation

MemoryObservation 是记忆原料，不是长期记忆。

```python
from datetime import datetime
from pydantic import BaseModel, Field


class MemoryObservation(BaseModel):
    observation_id: str
    student_id: str
    observation_type: ObservationType
    source_type: SourceType
    source_ref: str

    conversation_id: str | None = None
    turn_id: str | None = None
    event_id: str | None = None
    submission_id: str | None = None
    question_id: str | None = None
    question_state_version: int | None = None
    concept_ids: list[str] = Field(default_factory=list)

    content: str
    structured_payload: dict = Field(default_factory=dict)
    occurred_at: datetime | None = None
    observed_at: datetime
    schema_version: str = "memory-observation-v1"
```

### 4.1 创建规则

```text
学生自然语言原话 → student_statement。
正式答题事实 → formal_answer。
判题模块给出的确定错因 → verified_mistake。
教学系统实际采用某策略 → strategy_exposure。
后续正式作答改善 → outcome_evidence。
学生明确说“这个方法有帮助” → explicit_feedback。
```

禁止创建 Observation 的情况：

```text
纯系统日志。
模型内部思考过程。
没有学生或正式事件来源的推测。
尚未持久化的判题临时结果。
网络重放产生的同一来源事件。
```

### 4.2 Observation 幂等键

```python
observation_idempotency_key = sha256(
    f"{student_id}|{observation_type}|{source_type}|{source_ref}".encode()
).hexdigest()
```

同一来源、同一 Observation 类型只能保存一次。

## 5. DeepSeek 候选提取 Schema

DeepSeek 只处理自然语言中的 `preference` 和 `reflection`，以及明确的策略反馈。它不负责从作答结果判断重复错因。

### 5.1 输入

```python
class CandidateExtractionRequest(BaseModel):
    student_id: str
    observations: list[MemoryObservation]
    existing_candidates: list["ExistingCandidateSummary"] = Field(default_factory=list)
    extraction_schema_version: str = "memory-extractor-v1"


class ExistingCandidateSummary(BaseModel):
    candidate_id: str
    memory_key: str
    memory_type: MemoryType
    summary: str
    status: CandidateStatus
```

`existing_candidates` 只用于去重和发现可能的更新，不能作为新事实来源。

### 5.2 输出

```python
from typing import Literal


class ExtractedMemoryCandidate(BaseModel):
    memory_type: Literal["preference", "reflection", "effective_strategy"]
    dimension: str
    normalized_value: str
    scope_type: Literal["global", "concept", "question_type"]
    scope_ref: str | None = None
    summary: str

    evidence_observation_ids: list[str] = Field(min_length=1)
    evidence_quote: str
    source_role: Literal["student"]
    explicit: bool
    polarity: Literal["positive", "negative"]

    suggested_operation: Literal[
        "new_evidence",
        "possible_update",
        "possible_supersede",
        "none",
    ]
    related_candidate_id: str | None = None
    reason: str


class CandidateExtractionResult(BaseModel):
    candidates: list[ExtractedMemoryCandidate] = Field(default_factory=list)
    schema_version: str = "memory-extractor-v1"
```

### 5.3 memory_key 由代码生成

LLM 不允许自由生成正式 `memory_key`。代码根据结构化字段生成：

```python
def build_memory_key(candidate: ExtractedMemoryCandidate) -> str:
    scope = candidate.scope_ref or "global"
    return ":".join(
        [
            candidate.memory_type,
            candidate.scope_type,
            normalize_key_part(scope),
            normalize_key_part(candidate.dimension),
        ]
    )
```

示例：

```text
preference:global:global:hint_depth
preference:concept:fraction_addition:representation
reflection:global:global:learning_goal
```

重复错因使用确定性键：

```text
repeated_mistake:concept:{concept_id}:{mistake_code}
```

有效策略使用：

```text
effective_strategy:concept:{concept_id}:{strategy_code}
```

### 5.4 LLM 输出校验

代码必须逐项检查：

```text
evidence_observation_ids 全部存在且属于当前 student。
evidence_quote 能在对应学生原话中找到。
source_role 必须为 student。
preference 和 reflection 必须 explicit=true 才能直接进入评估。
输出不得引用 assistant 回复作为学生偏好证据。
输出不得包含 mastery、正确率或重复错因结论。
related_candidate_id 必须属于当前 student。
```

任一检查失败，该候选拒绝，错误码为 `memory_extraction_invalid_evidence`。

## 6. MemoryCandidate

```python
class MemoryCandidate(BaseModel):
    candidate_id: str
    student_id: str
    memory_key: str
    memory_type: MemoryType

    dimension: str
    normalized_value: str
    scope_type: str
    scope_ref: str | None = None
    summary: str

    status: CandidateStatus
    confidence: float = Field(ge=0.0, le=1.0)
    evidence_count: int = Field(ge=0)
    independent_evidence_count: int = Field(ge=0)

    first_observed_at: datetime
    last_observed_at: datetime
    supersedes_candidate_id: str | None = None
    superseded_by_candidate_id: str | None = None
    rejection_code: str | None = None
    rejection_detail: str | None = None

    extractor_model: str | None = None
    extractor_schema_version: str | None = None
    gate_rule_version: str = "memory-gate-v1"
    created_at: datetime
    updated_at: datetime
```

`confidence` 只是排序和审核辅助字段，不能替代证据门槛。

### 6.1 状态流转

```text
pending -> waiting_evidence
pending -> approved
pending -> rejected
waiting_evidence -> approved
waiting_evidence -> rejected
approved -> disabled
disabled -> approved
approved -> superseded
disabled -> superseded
approved -> deleted
disabled -> deleted
```

禁止流转：

```text
rejected 不能直接变 approved；必须创建新 Candidate 或重新进入 pending 审核。
superseded 不能重新启用；需要创建新 Candidate。
deleted 不能恢复；重新记忆必须创建新 Candidate 和新审核记录。
HMS 同步成功不能反向改变业务状态。
```

## 7. CandidateEvidence

候选和 Observation 是多对多关系，单独建关联表：

```python
class CandidateEvidence(BaseModel):
    candidate_id: str
    observation_id: str
    evidence_role: Literal[
        "explicit_statement",
        "mistake_occurrence",
        "strategy_exposure",
        "positive_outcome",
        "negative_outcome",
        "superseding_statement",
    ]
    independent_group_key: str
    added_at: datetime
```

`independent_group_key` 用于防止重复计数。

示例：

```text
正式作答：submission:{submission_id}
同一题状态：question-state:{student_id}:{question_id}:{question_state_version}
学生明确表达：turn:{conversation_id}:{turn_id}
策略使用：trace:{trace_id}:{strategy_code}
```

相同 `independent_group_key` 对同一候选只计一次。

## 8. 证据门控规则

### 8.1 preference

批准条件：

```text
至少 1 条 explicit_statement。
证据来自学生原话。
evidence_quote 校验通过。
不是仅针对当前题的临时指令，或者 scope 已明确限定。
```

### 8.2 reflection

批准条件：

```text
至少 1 条 explicit_statement。
内容属于学习目标、自我观察或复盘。
不能由系统总结冒充学生原话。
```

### 8.3 repeated_mistake

批准条件：

```text
至少 2 个不同 submission_id。
至少 2 个不同 independent_group_key。
concept_id 相同。
mistake_code 相同。
每次错因都来自判题规则或步骤证据。
不能包含提交前已查看答案、无法判题或聊天草稿。
```

是否进入 KT 与是否能成为错因证据分开：

```text
eligible_for_kt=false 的作答默认不计入 repeated_mistake。
如果未来需要纳入，必须新增 ADR 和单独证据角色，不能静默改变。
```

### 8.4 effective_strategy

批准条件：

```text
至少 1 条 strategy_exposure。
至少 1 条发生在策略使用之后的 positive_outcome。
outcome 对应同一学生和相同或明确相关的 concept_id。
AI 自己说“有效”不算 positive_outcome。
```

### 8.5 规则接口

## 9. 查重、更新和冲突

按以下顺序处理：

```text
1. 精确查询相同 memory_key。
2. 查询相同 memory_type + scope 的当前候选。
3. 对已经写入 HMS 的正式记忆，使用 BGE-M3 找 top_k=5 的可能重复项。
4. 代码比较规范化字段。
5. 必要时让 LLM提出 possible_update / possible_supersede 建议。
6. 代码最终执行 merge、supersede 或 new。
```

### 9.1 精确重复

相同 `memory_key`：

```text
不创建第二条 active candidate。
新增 CandidateEvidence。
重新计算 evidence_count 和 gate 状态。
```

### 9.2 内容更新

相同维度、相同方向、内容更具体：

```text
保留 candidate_id。
更新 normalized_value 和 summary。
新增证据。
创建新的 Promotion 审核记录。
HMS 使用相同 document_id 执行 replace。
```

### 9.3 状态冲突

例如“喜欢详细讲解”变为“只要第一步提示”：

```text
创建新 candidate。
新 candidate 通过明确证据门控后批准。
旧 candidate 标记 superseded。
双方记录 supersedes / superseded_by。
先让旧记忆退出召回，再异步替换 HMS document。
```

Embedding 相似度只能产生“可能重复”候选，不能直接合并或删除。

pending / waiting_evidence Candidate 不单独建立向量索引，第一阶段只使用 `memory_key`、规范字段和 scope 查重，避免维护第二套向量库。

```python
    text: str
    memory_key: str | None
    memory_type: MemoryType | None
    metadata: dict[str, str]
    tags: list[str]

    async def health(self) -> bool: ...
```

### 13.2 标识生成

```python
def hms_bank_id(student_id: str, secret: bytes) -> str:
    digest = hmac_sha256(secret, student_id.encode()).hexdigest()[:32]
    return f"student-{digest}"


def hms_document_id(memory_key: str) -> str:
    digest = sha256(memory_key.encode()).hexdigest()[:32]
    return f"memory-{digest}"
```

不能把姓名、手机号或原始 student_id 暴露在 HMS bank_id 中。

## 15. 事务边界

### 15.1 保存 Observation

一个 SQLite 事务：

```text
INSERT memory_observations
INSERT memory_jobs(memory_candidate_extract)
COMMIT
```

如果 Observation 已存在，不重复创建提取任务。

### 15.2 批准 Candidate

一个 SQLite 事务：

```text
UPDATE memory_candidates status=approved
INSERT memory_promotions sync_status=pending
INSERT memory_jobs(hms_retain)
COMMIT
```

事务提交后 Worker 才能调用 HMS。

### 15.3 HMS 写入成功

```text
调用 HMS retain
→ SQLite 事务更新 promotion.sync_status=succeeded
→ 保存 hms_bank_id、hms_document_id、hms_unit_ids
→ job 标记 completed
```

不能让数据库事务跨越远程 HTTP 调用。

### 15.4 删除

```text
SQLite 事务先把 candidate 标记 deleted
→ 追加 delete promotion
→ 清除该 memory_key 的召回缓存
→ 创建 hms_delete job
→ 提交事务
→ Worker 异步调用 HMS delete_document
```

这样即使 HMS 暂时不可用，记忆也会立即退出 MathTutor 上下文。

### 15.5 禁用与重新启用

禁用：

```text
SQLite 事务把 approved Candidate 标记 disabled
→ 追加 disable Promotion
→ 清除召回缓存
→ 创建 hms_delete job
→ 提交事务
```

重新启用：

```text
重新校验原 evidence_refs 仍然存在
→ SQLite 事务把 disabled Candidate 标记 approved
→ 追加 enable Promotion
→ 创建 hms_retain job
→ 提交事务
```

禁用不会删除候选和证据；删除是不可恢复操作。

### 16.2 重试策略


代码先判断场景，再决定是否访问 HMS：

```python
MEMORY_RECALL_POLICY = {
```


HMS 分数表示相关程度，不表示记忆事实可信度。可信度从本地审核账本读取。

## 20. 现有代码迁移

当前代码的问题：

```text
StudentMemory 同时承担候选、正式记忆和召回结果。
write() 根据正文和少量 evidence 字段直接查重。
MathTutorLearningLoop._update_memory() 可以直接写长期记忆。
MathTutorLearningLoop._load_context() 每轮直接查询记忆。
Mem0 Provider 与新的 HMS 选型不一致。
```

迁移顺序：

```text
1. 新增模型、Repository 和表，不修改旧 API。
2. 实现 LearningMemorySystem.observe()，但先只记录 Observation。
3. 把 _update_memory() 替换为 observe()，停止直接 write(StudentMemory)。
4. 实现候选提取、证据门控和任务 Worker。
5. 实现 HMSLongTermMemoryAdapter。
6. 把 _load_context() 的直接 search() 收进 LearningContextLayer。
7. 控制 API 改为按 memory_key 操作 approved candidate。
8. 确认无旧调用后删除 Mem0 live provider 路径。
9. StudentMemoryStore 保留为兼容外壳一个版本，再删除。
```

旧 `student_memories` 数据不自动视为正式记忆。迁移脚本必须：

```text
为每条旧记忆创建 legacy_import Observation。
创建 pending Candidate。
重新执行门控。
审核通过后写 HMS。
无法回溯证据的旧记忆保持 disabled，不自动进入召回。
```


## 22. 最终开发契约

第一阶段必须遵守：

```text
Observation 只是原料。
Candidate 只是可能成立的结论。
Promotion 是不可变审核记录。
只有 approved Candidate 才能创建 hms_retain 任务。
只有 sync_status=succeeded 的正式记忆才能正常参与 HMS 召回。
业务查重和清理决定属于 MathTutor。
HMS 只负责正式记忆的存、找、换、删。
DeepSeek 只提取候选，不决定长期画像。
BGE-M3 只计算语义向量，不判断事实真假。
判题和 KT 永远高于记忆内容。
```
