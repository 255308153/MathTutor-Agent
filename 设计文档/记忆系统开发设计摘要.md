# MathTutor Agent 记忆系统开发设计摘要

> 状态：已废弃的 HMS / Graphiti 融合讨论稿。正式实施依据见 `记忆模块开发设计（HMS落地版）.md` 和 `记忆模块数据与接口详细设计.md`。

## 1. 模块目标

```text
从学生的长期对话和学习事实中，
提炼有证据、可更新、可删除、以后仍有教学价值的长期记忆，
并在需要时向上下文模块返回少量相关证据。
```

记忆模块解决的是：

```text
学生偏好什么讲解方式。
学生是否反复出现同一种确定错因。
某种教学策略是否经过后续结果验证有效。
学生有哪些明确学习目标和反思。
旧记忆何时被新证据更新或替代。
```

---

## 2. 模块边界

### 2.1 负责

```text
保存当前 conversation 的短期对话。
接收对话和学习事实产生的 MemoryObservation。
提取 MemoryCandidate。
检查证据、质量、重复和冲突。
维护正式长期记忆及其状态。
调用 HMS 保存和召回正式记忆。
把 HMS 中审核通过的正式记忆关系投影到 Graphiti。
按意图返回少量相关记忆证据。
处理 Provider 超时、失败、重试和降级。
```

### 2.2 不负责

```text
不负责判题。
不保存正式作答和判题事实。
不决定作答能否进入 KT。
不计算 mastery、预测概率和遗忘风险。
不检索教材和题目解析。
不推荐下一题。
不生成最终教学回复。
```

## 3. 总体架构

```text
对话 / 已保存的学习事实
        ↓
MemoryObservation
        ↓
MemoryCandidateExtractor
        ↓
MemoryQualityGate
        ↓
查重、冲突判断、证据门槛
        ↓
正式长期记忆
        ↓
HMS Retain                # 正式记忆和原始证据
        ↓
GraphProjectionWorker
        ↓
Graphiti / Neo4j          # 派生关系图
```

读取流程：

```text
MemoryContextRequest
        ↓
HMS Recall                # 找具体记忆和 source snippets
        ↓
按需 Graphiti 扩展         # 找学生、知识点、错因和策略关系
        ↓
去重、证据校验
        ↓
MemoryEvidenceLedger
        ↓
MemoryContextResult
        ↓
上下文模块
```

## 4. HMS 和 Graphiti 的分工

### HMS：正式记忆权威

HMS 负责回答：

```text
记住了什么？
这条记忆来自哪里？
什么时候发生、什么时候被提到？
有哪些原始 source snippets？
有多少条证据支持？
与旧记忆相比是否发生更新？
```

HMS 保存：

```text
正式记忆内容。
原始证据引用。
occurred_at 和 mentioned_at。
proof_count。
source_memory_ids。
记忆状态和变化历史。
```

### Graphiti：关系增强

Graphiti 负责回答：

```text
学生与哪些错因有关？
错因出现在哪些知识点？
学生偏好哪种讲解方式？
哪些教学策略曾对该学生有效？
新旧关系如何替代？
```

Graphiti 只接收 HMS 中已经审核通过的正式记忆，不读取原始聊天，不独立创造学生事实。

每条 Graphiti 关系必须带：

```text
hms_memory_id
hms_observation_id
source_memory_ids
student_id
confidence
valid_from
valid_to
```

找不到 HMS 原始记忆和证据的 Graphiti 关系，不允许进入学生回复。

## 5. 记忆类型和写入门槛

### preference：学习偏好

可以来自学生明确表达：

```text
“我更喜欢画图讲。”
“先给我提示，不要直接给完整答案。”
```

系统推测的偏好只能作为候选，不能直接成为正式记忆。

### repeated_mistake：重复错因

必须满足：

```text
至少两次独立正式作答。
不是同一 question_state_version 的重复尝试。
属于相同知识点和相同确定错因。
错因有判题规则或步骤证据支持。
```

一次答错不能形成 repeated_mistake。

### effective_strategy：有效教学策略

必须同时存在：

```text
strategy_exposure：系统确实使用过该策略。
outcome_evidence：之后出现明确正面反馈或正式作答改善。
```

AI 自己说“这个策略有效”不能成为证据。

### reflection：学习目标和反思

主要来自学生明确表达：

```text
“我想先把分数运算补起来。”
“我发现自己总是忘记检查符号。”
```

## 6. 写入流程

```text
对话或学习事实已经保存
  → 创建 MemoryObservation
  → 持久化 memory_refinery_job
  → DeepSeek V4 Pro 提取 MemoryCandidate
  → 校验证据引用
  → 查重和冲突判断
  → 未达到门槛：保留候选或拒绝
  → 达到门槛：写入 HMS
  → HMS 成功后创建 Graphiti projection job
  → 投影审核后的关系
```

记忆写入不在判题、提交答案或回复请求中同步完成。

禁止直接使用 HMS 的“包装所有 LLM 调用并自动 Retain”作为正式写入规则。

---

## 7. 读取策略

| 场景 | HMS | Graphiti |
|---|---:|---:|
| 提交答案 | 不查 | 不查 |
| 普通闲聊 | 不查 | 不查 |
| 普通概念问题 | 通常不查 | 不查 |
| 当前题求助 | 按需 | 通常不查 |
| 错因解释 | 查 | 按需查关系 |
| 下一步建议 | 查 | 按需查关系 |
| 推荐原因 | 可选 | 可选 |
| 学习复盘 | 查 | 查 |

每轮最多返回 3～5 条正式记忆，同一类型最多 2 条。

## 8. MemoryEvidenceLedger

召回结果不能直接交给回复模型，必须先组织成证据账本。

```python
class MemoryEvidenceRow(BaseModel):
    memory_id: str
    memory_type: str
    summary: str
    occurred_at: str | None
    mentioned_at: str | None
    confidence: float
    proof_count: int
    source_memory_ids: list[str]
    source_refs: list[str]
    graph_paths: list[dict]
    status: str
```

账本负责：

```text
去除重复事件。
区分当前状态和历史状态。
保留发生时间和提及时间。
保留原始证据引用。
标记证据缺口。
禁止把缺失值当成 0 或 false。
```

MemoryEvidenceLedger 由上下文模块组织，记忆模块提供召回结果和证据引用。

## 9. 外部接口

```python
class LearningMemorySystem:
    def observe(self, observation: MemoryObservation) -> ObservationReceipt:
        """保存记忆原料并创建后台提炼任务。"""

    def context_for(self, request: MemoryContextRequest) -> MemoryContextResult:
        """按意图召回正式记忆和证据引用。"""

    def disable(self, memory_id: str) -> None:
        """停止记忆参与检索。"""

    def delete(self, memory_id: str) -> None:
        """删除正式记忆并传播到 HMS 和 Graphiti。"""
```

调用方不能直接使用 HMS SDK 或 Graphiti SDK。

## 10. 故障处理

### HMS 写入失败

```text
MemoryObservation 和 Candidate 仍保存在本地任务表。
创建 HMS retain 重试任务。
不写 Graphiti。
不阻断学习主流程。
```

### HMS 查询失败

```text
返回空记忆。
记录 memory_provider_failure。
Graphiti 关系不能脱离 HMS 证据单独进入回复。
判题、KT、RAG 和回复继续。
```

### Graphiti 失败

```text
继续使用 HMS Recall。
记录 graph_enrichment_unavailable。
投影任务后台重试。
不影响正式记忆。
```

### DeepSeek V4 Pro 失败

```text
候选提取任务进入重试。
不使用不完整输出写正式记忆。
不影响已存在记忆的读取。
```

## 11. 技术选择

```text
部署目标：个人或少量用户的真实可运行系统。
记忆主系统：HMS。
HMS 存储：PostgreSQL + pgvector。
关系增强：Graphiti + Neo4j。
候选提取模型：云端 DeepSeek V4 Pro。
Embedding 模型：待确定。
后台任务：第一阶段使用持久任务表和单 Worker。
```

HMS 当前属于较新的外部项目，因此必须放在 `HMSMemoryAdapter` 后面，不能让业务代码与其 SDK 直接绑定。

## 12. 开发阶段

### Phase 1：记忆边界和原料

```text
实现 LearningMemorySystem 接口。
保存 conversation_turns。
实现 MemoryObservation、Candidate 和持久任务表。
停止一次答错或答对直接写长期记忆。
```

### Phase 2：HMS 验证接入

```text
部署 PostgreSQL + pgvector 和 HMS。
实现 HMSMemoryAdapter。
使用 DeepSeek V4 Pro 完成 Retain / Recall 验证。
建立 MathTutor 专用小型记忆测试集。
```

### Phase 3：质量门控和正式记忆

```text
实现四类记忆写入规则。
实现证据检查、查重、冲突和状态变化。
实现 HMS 写入重试和删除传播。
```

### Phase 4：Evidence Ledger

```text
保留 source snippets、occurred_at 和 mentioned_at。
实现 proof_count 和 source_memory_ids。
上下文模块实现 MemoryEvidenceLedger。
```

### Phase 5：Graphiti 关系增强

```text
实现 GraphProjectionWorker。
只投影 HMS 正式记忆。
实现 Graphiti 关系召回、去重和证据回链。
Graphiti 故障时继续使用 HMS。
```

## 13. 验收标准

```text
一次答错不会形成重复错因。
两次独立、确定的相同错因可以形成正式记忆。
HMS 中每条正式记忆都能回到原始证据。
Graphiti 每条关系都能回到 HMS memory_id。
Graphiti 不能脱离 HMS 证据生成学生事实。
Memory 不能写 mastery 和 prediction_probability。
提交答案和闲聊不查询长期记忆。
HMS 或 Graphiti 失败不阻断判题和 KT。
重复后台任务不产生重复记忆或关系。
删除记忆后 HMS、Graphiti 和上下文均不可再检索。
不同 student_id 的记忆完全隔离。
缺少证据时返回 unknown 或 evidence_gap，不猜测。
```
