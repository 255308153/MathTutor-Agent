# MathTutor Agent 上下文模块开发设计

## 1. 文档说明

本文档把 `重构思考/上下文总设计.md` 中的产品规则细化为可以实施的技术方案。

本文重点回答：

```text
上下文模块负责什么，不负责什么。
系统如何先识别场景，再决定读取哪些资料。
当前对话、正式学习事实、长期画像和 RAG 如何分开。
点击“下一题”时为什么需要选题前、选题后两次组装。
Graphiti 如何保存长期关系记忆，又不污染 KT 权威事实。
LLMLingua 如何压缩软证据，又不破坏数学条件和引用。
现有 LearningContextLayer 应当怎样改造成调用方不能绕开的深模块。
现有代码需要修改哪些文件、按什么顺序实施、怎样测试。
```

本文只设计上下文的读取、选择、压缩、组装和审计，不重新定义 KT（知识追踪）、RAG（检索增强生成）、记忆提炼、判题或推荐算法。

---

## 2. 一句话目标

```text
先判断学生这一轮要做什么，再从多个数据源中只取需要的资料，
按照权威性和相关性装成一个受预算控制、可以追踪来源的小包。
```

上下文模块只决定：

```text
这一轮允许看见什么。
```

上下文模块不能决定：

```text
学生会不会。
答案对不对。
掌握度应该是多少。
下一题最终选哪一道。
长期画像是否已经成立。
```

---

## 3. 已确定的技术选择

### 3.1 保留现有 Runtime（运行时）

继续使用：

```text
MathTutorAgentRuntime
MathTutorLearningLoop
LangGraph（图式编排框架）
LearningContextLayer
MathToolRegistry（数学工具注册表）
TeachingTrace（教学执行追踪）
```

不引入第二套 Agent Runtime（智能体运行时）。Letta 只作为分层记忆设计参考，不接管 MathTutor 的主编排。

### 3.2 Graphiti 作为长期关系记忆层

Graphiti 负责保存带时间、来源和关系的长期学生画像，例如：

```text
学生偏好什么讲法。
学生在哪些知识点反复出现同类错因。
某种教学策略曾经在什么条件下有效。
旧偏好什么时候被新偏好替代。
```

Graphiti 不是 KT、判题、当前题或正式学习事件的唯一数据源。

### 3.3 LLMLingua 作为可选压缩器

LLMLingua 只压缩较长的软证据：

```text
对话历史。
RAG 正文。
长期记忆说明。
题目候选摘要。
```

默认使用 `NoOpCompressor（不压缩实现）`，没有模型或运行资源时不影响主流程。

### 3.4 一个上下文模块，两种组装阶段

继续使用一个 `LearningContextLayer`，不建立两套平行上下文模块。

通过 `phase（组装阶段）`区分：

```text
selection：选题阶段。
response：回答阶段。
```

## 4. 当前实现与目标差距

当前主要代码位于：

```text
backend/app/context/learning_context.py
backend/app/graph/learning_loop.py
backend/app/runtime/agent_runtime.py
backend/app/runtime/context.py
backend/app/runtime/governance.py
backend/app/runtime/tools.py
backend/app/schemas/learning.py
backend/app/planning/teaching_planner.py
backend/app/planning/recommender.py
```

已有能力：

```text
ContextAsset（上下文资产）统一模型。
按类型、来源、学生、会话、题目和知识点检索。
优先级排序和 Token（文本计量单位）预算裁剪。
selected、omitted 和 evidence_gap 记录。
KT 权威事实与普通上下文资产分开。
ResponseContextPackage（回答上下文包）排除原始 Provider 数据。
TeachingTrace 中的治理审计。
```

主要问题：

1. `MathTutorLearningLoop._load_context()` 每轮都会读取长期记忆和 RAG。
2. `answer_submission（提交答案）`仍然会组装回答上下文、生成回复并自动推荐。
3. `next_step_advice（下一步建议）`当前会调用推荐器并修改 `pending_question`。
4. 只有三个粗粒度意图，`general_chat（一般对话）`无法区分闲聊、概念提问和当前题求助。
5. 没有独立的 `conversation_id（聊天窗口编号）`。
6. 调用方先查 Memory、RAG，再把结果交给上下文层，上下文层不是唯一读取入口。
7. `TeachingPlanner`仍然接收原始 `rag_context` 和 `recommended_questions`。
8. 当前预算只按字符估算，没有压缩器接口和不可压缩字段声明。
9. 当前没有 Graphiti 长期关系记忆适配器。

## 5. 总体架构

```text
LearningEvent（学习事件）
        ↓
IntentRouter（意图路由器）
        ↓
ContextPolicy（上下文读取策略）
        ↓
LearningContextLayer
    ├── TeachingStateReader（教学状态读取器）
    ├── LearningFactReader（正式学习事实读取器）
    ├── ConversationReader（当前对话读取器）
    ├── GraphitiMemoryAdapter（长期关系记忆适配器）
    ├── RAGReader（知识资料读取器）
    └── QuestionCandidateReader（候选题摘要读取器）
        ↓
ContextSelector（上下文选择器）
        ↓
ContextCompressor（上下文压缩器）
    ├── NoOpCompressor
    └── LLMLinguaCompressor
        ↓
AssembledContext（组装后上下文）
        ↓
Planner / Recommender / ResponseGenerator
        ↓
TeachingTrace
```

主调用方只允许调用：

```python
assembled_context = context_layer.build(request)
```

主调用方不能直接查询 Graphiti、RAG、长期记忆 Provider 或对话存储。

## 6. 身份字段

```text
student_id：学生编号，长期学习状态和画像按它共享。
session_id：一次连续学习过程的编号。
conversation_id：一个 Agent 聊天窗口的编号。
turn_id：一次学生输入和系统回复的编号。
event_id：一次正式学习事件的编号。
trace_id：一次执行和证据审计的编号。
```

兼容旧请求：

```text
conversation_id = "legacy:" + session_id
```

新开聊天窗口时：

```text
创建新的 conversation_id。
当前对话窗口为空。
student_id 和 session_id 不变。
当前题、KT、TeachingState、正式学习事实和长期画像不变。
```

`conversation_id`不能继续用 `session_id`代替。一个学习过程内可以新开多个聊天窗口。

## 7. 系统事件与聊天意图

### 7.1 系统事件

```text
answer_submitted：提交答案。
next_question_requested：点击下一题。
question_changed：换题。
answer_revealed：查看答案。
question_skipped：跳过题目。
```

### 7.2 聊天意图

```text
small_talk：闲聊。
concept_question：泛化概念问题。
current_question_help：当前题求助。
mistake_explanation：追问错因。
next_step_advice：询问下一步学习方向。
recommendation_reason：询问推荐原因。
review_summary：学习复盘。
```

系统事件由事件类型直接确定。聊天意图由规则优先、LLM 分类可选的方式确定。

第一期规则识别不确定时，回退到：

```text
general_chat -> concept_question
```

回退不能触发 KT 更新、推荐或切题。

## 8. ContextPolicy（上下文策略）

`ContextPolicy`是确定性配置，不交给 LLM 自由决定。

```python
class ContextPolicy(BaseModel):
    intent: str
    phase: str | None
    include_teaching_state: bool
    include_learning_facts: bool
    include_conversation: bool
    include_long_term_memory: bool
    include_rag: bool
    include_question_candidates: bool
    conversation_turn_limit: int = 5
    memory_limit: int = 5
    rag_limit: int = 3
    token_budget: int = 1200
```

场景策略：

| 场景 | TeachingState | 学习事实 | 短对话 | Graphiti | RAG | 候选题 |
|---|---:|---:|---:|---:|---:|---:|
| 闲聊 | 否 | 否 | 是 | 否 | 否 | 否 |
| 概念问题 | 一般否 | 可选 | 是 | 一般否 | 可选 | 否 |
| 当前题求助 | 可选 | 是 | 是 | 可选 | 本题资料 | 否 |
| 追问错因 | 是 | 是 | 是 | 可选 | 本题和错因资料 | 否 |
| 下一步建议 | 是 | 是 | 是 | 可选 | 一般否 | 否 |
| 点击下一题，选题阶段 | 是 | 是 | 可选摘要 | 可选 | 否 | 是 |
| 点击下一题，回答阶段 | 是 | 是 | 可选摘要 | 已选内容 | 只查选中题 | 否 |
| 推荐原因 | 是 | 当时推荐证据 | 是 | 当时选中内容 | 当时引用 | 否 |
| 复盘总结 | 是 | 是 | 是 | 可选 | 可选 | 否 |
| 提交答案 | 不构建回答上下文 | 保存和更新事实 | 否 | 否 | 否 | 否 |

## 10. ContextAsset（上下文资产）调整

保留现有五类资产，并增加当前对话资产：

```text
student_memory：长期学生画像。
conversation_turn：当前聊天窗口的短期对话。
knowledge_resource：RAG 知识资料。
task_state：当前题、作答、判题和正式学习事实。
tool_observation：工具结果摘要。
trace_reference：审计引用。
question_candidate：候选题摘要，只用于 selection 阶段。
```

建议增加字段：

```python
class ContextAsset(BaseModel):
    # 保留现有字段
    authority: Literal["authoritative", "supporting", "advisory", "debug"]
    compressible: bool = True
    required: bool = False
    phase: ContextPhase | None = None
    relevance_score: float = 0.0
    source_timestamp: str | None = None
    provenance: dict[str, Any] = Field(default_factory=dict)
```

字段含义：

```text
authority：这条内容的权威等级。
compressible：是否允许被 LLMLingua 压缩。
required：是否属于不可裁剪的核心内容。
phase：只在哪个组装阶段可用。
relevance_score：与本轮目标的相关程度。
source_timestamp：原始事实发生时间。
provenance：来源、版本和证据引用。
```

## 11. AssembledContext（组装后上下文）

在现有模型上增加：

```python
class AssembledContext(BaseModel):
    context_id: str
    parent_context_id: str | None = None
    phase: ContextPhase
    intent: str
    student_id: str
    session_id: str
    conversation_id: str
    authoritative_kt_facts: dict[str, Any]
    normalized_context: dict[str, Any]
    asset_selection: dict[str, list[dict[str, Any]]]
    evidence_gaps: list[dict[str, Any]]
    evidence_refs: list[str]
    budget_used: int
    budget_limit: int
    compression_summary: dict[str, Any]
    context_invariants: dict[str, str]
```

`normalized_context`建议统一为：

```json
{
  "task_state": [],
  "conversation_window": [],
  "student_memory": [],
  "knowledge_resource": [],
  "question_candidates": [],
  "tool_observations": []
}
```

`selection`阶段不得包含任意候选题的完整解析。

`response`阶段只允许包含最终选中题目的解析，不允许带其它候选题题解。

## 12. LearningContextLayer 外部接口

```python
class LearningContextLayer:
    def build(self, request: ContextBuildRequest) -> AssembledContext:
        """按场景读取、选择、压缩和组装本轮上下文。"""
```

模块内部流程：

```text
1. 根据 intent 和 phase 读取 ContextPolicy。
2. 校验请求是否允许构建上下文。
3. 只调用策略要求的数据读取器。
4. 把读取结果转成 ContextAsset。
5. 校验题目、知识点、学生和对话范围。
6. 应用记忆禁用、删除、过期和置信度规则。
7. 按权威性、目标匹配、相关性、新鲜度排序。
8. 先保留 required 资产。
9. 对可压缩软证据执行 ContextCompressor。
10. 按预算选择其余资产。
11. 生成 evidence_gap、selected、compressed 和 omitted 记录。
12. 保存 ContextAssemblyRecord 并写 TeachingTrace。
```

调用方不再分别调用：

```text
memories.search()
rag.search()
context_layer.collect_assets()
context_layer.retrieve_assets()
context_layer.assemble_context()
```

这些操作收进 `LearningContextLayer.build()`内部。

## 13. 上下文选择顺序

固定优先级：

```text
1. authoritative_kt_facts：KT / DGEKT 权威事实。
2. required task_state：当前题、学生答案、判题结果和本轮正式事件。
3. relevant task_state：近期作答、推荐证据和换题反馈。
4. conversation_turn：当前聊天窗口最近 3～5 轮。
5. student_memory：与本轮相关的长期学生画像。
6. knowledge_resource：与当前题或知识点匹配的 RAG 资料。
7. question_candidate：选题阶段的候选题摘要。
8. tool_observation：工具结果摘要。
9. trace_reference：调试和审计引用。
```

实际排序键建议为：

```text
required
authority
question_id 精确匹配
concept_id 精确匹配
conversation_id 精确匹配
intent 适配
relevance_score
freshness
confidence
updated_at
```

不能只按文本相似度排序。

## 14. Token 预算与裁剪

预算分为三部分：

```text
hard_budget：权威事实和当前题核心，不可裁剪。
soft_budget：对话、记忆和 RAG，可以压缩或裁剪。
audit_budget：只保留引用编号和裁剪原因。
```

第一期默认：

```text
总预算：1200 个近似 Token。
当前对话：最多 5 轮。
长期记忆：最多 5 条。
RAG：最多 3 条。
候选题：最多保留推荐器需要的摘要字段。
```

预算不足时：

```text
先压缩软证据。
再裁掉低相关、低置信度和过期内容。
KT 和当前题核心内容仍然保留。
每一条裁剪都记录 excluded_reason。
```

如果不可裁剪内容本身超过预算：

```text
不截断数学条件。
记录 hard_budget_exceeded。
允许本轮超过软预算。
在 Trace 中标记需要提高预算或缩短上游正式快照。
```

## 16. Graphiti 接入设计

### 16.1 接入方式

新增适配器，不让业务代码直接依赖 Graphiti SDK：

```python
class LongTermContextStore(Protocol):
    def search(self, request: LongTermContextQuery) -> list[LongTermContextFact]: ...
    def upsert(self, facts: list[LongTermContextFact]) -> None: ...


class LocalLongTermContextStore(LongTermContextStore): ...
class GraphitiLongTermContextStore(LongTermContextStore): ...
```

这里存在两个真实 Adapter（适配器）：本地实现和 Graphiti 实现，因此这条 seam（可替换位置）是必要的。

### 16.2 Graphiti 保存什么

节点示例：

```text
Student（学生）
Concept（知识点）
MistakePattern（错因模式）
TeachingStrategy（教学策略）
LearningPreference（学习偏好）
LearningGoal（学习目标）
```

关系示例：

```text
Student -> PREFERS -> LearningPreference
Student -> REPEATEDLY_MAKES -> MistakePattern
MistakePattern -> OCCURS_IN -> Concept
TeachingStrategy -> HELPED -> Student
Student -> PURSUES -> LearningGoal
```

每条关系必须带：

```text
student_id
source_type
source_id
evidence_refs
confidence
valid_from
valid_to
created_at
updated_at
```

### 16.3 Graphiti 不保存什么

禁止把以下内容交给 Graphiti 决定：

```text
mastery
prediction_probability
weak_concepts
forgetting_risks
正式判题结果
current_question
pending_question
一次聊天中的未经确认推测
```

这些内容可以作为只读查询条件或来源引用，但不能由 Graphiti 输出覆盖。

### 16.4 写入入口

Graphiti 只接受 `LearningMemoryRefinery（学习记忆提炼器）`审核通过的长期事实。

```text
对话 / 学习事件
  -> MemoryObservation（记忆原料）
  -> MemoryCandidate（记忆候选）
  -> 证据检查、查重和冲突判断
  -> 正式长期记忆
  -> GraphitiLongTermContextStore.upsert()
```

`LearningContextLayer`只有读取权限，不负责创建长期画像。

### 16.5 运行方式

依赖作为可选项：

```toml
[project.optional-dependencies]
graphiti = ["graphiti-core"]
```

配置示例：

```text
MATHTUTOR_LONG_TERM_CONTEXT_BACKEND=local|graphiti
MATHTUTOR_GRAPHITI_DRIVER=neo4j|falkordb|kuzu
MATHTUTOR_GRAPHITI_URI=
MATHTUTOR_GRAPHITI_USER=
MATHTUTOR_GRAPHITI_PASSWORD=
```

默认 `local`，Graphiti 不可用时回退本地长期记忆检索并记录 Provider gap（提供方缺口），不能阻断学习流程。

## 17. LLMLingua 接入设计

### 17.1 接口

```python
class ContextCompressor(Protocol):
    def compress(self, request: CompressionRequest) -> CompressionResult: ...


class NoOpCompressor(ContextCompressor): ...
class LLMLinguaCompressor(ContextCompressor): ...
```

这里同样有两个真实实现，适配器位置成立。

### 17.2 压缩请求

```python
class CompressionRequest(BaseModel):
    intent: str
    phase: ContextPhase
    query: str
    assets: list[ContextAsset]
    target_budget: int
    protected_terms: list[str]
```

`protected_terms（保护词）`至少包含：

```text
question_id
concept_id
citation_id
数学符号
变量名
数值
单位
否定词
条件词
```

### 17.3 禁止压缩

以下资产必须设置 `compressible = false`：

```text
KT 权威事实。
当前题完整题干。
学生正式答案。
标准答案。
判题结果。
数学公式和限制条件。
引用编号、来源和证据定位。
推荐器必须使用的结构化数值字段。
```

### 17.4 压缩结果

每条结果记录：

```text
asset_id
original_cost
compressed_cost
compression_ratio
compressor_name
compressor_version
protected_terms_preserved
fallback_used
```

压缩后必须执行完整性检查：

```text
引用编号仍然存在。
题目和知识点编号没有变化。
数字、单位和数学符号没有被修改。
没有增加原文中不存在的事实。
```

检查失败时使用原始摘要或 `NoOpCompressor`结果。

### 17.5 运行配置

```toml
[project.optional-dependencies]
compression = ["llmlingua"]
```

```text
MATHTUTOR_CONTEXT_COMPRESSOR=none|llmlingua
MATHTUTOR_CONTEXT_COMPRESSION_MODEL=
MATHTUTOR_CONTEXT_COMPRESSION_MIN_TOKENS=800
MATHTUTOR_CONTEXT_COMPRESSION_TARGET_RATIO=0.5
```

小于触发阈值时不调用 LLMLingua。

## 18. 点击“下一题”的两阶段流程

### 18.1 selection phase（选题阶段）

```text
next_question_requested
  -> 读取最新 TeachingState
  -> 读取近期正式作答
  -> 读取最近换题反馈
  -> 按需读取 Graphiti 长期偏好
  -> 读取候选题摘要
  -> CandidateKTScorer 对初筛候选题批量计算 SAFKT 目标题概率
  -> build(phase="selection")
  -> Recommender 只读取 selection 上下文
  -> 选出一道题
```

候选题只提供：

```text
question_id
concept_id
difficulty
teaching_type
content_availability
近期是否做过
必要的题型标签
SAFKT 目标题概率（已完成评分时）
评分状态和 TeachingState 引用
```

选题前不查询候选题的完整解析。

### 18.2 response phase（回答阶段）

```text
确定 selected_question
  -> 只查询该题解析和引用
  -> build(phase="response", parent_context_id=selection_context_id)
  -> 保存 current_question
  -> 生成简短推荐理由
```

回答资料包可以继承选题包中的已选证据引用，但必须重新执行预算和数据范围检查。

## 19. “下一步练什么”的聊天流程

```text
chat_message
  -> intent = next_step_advice
  -> 读取 TeachingState、近期作答和当前对话短现场
  -> 按需读取长期画像
  -> 不读取候选题
  -> 不调用 Recommender
  -> 不修改 current_question 或 pending_question
  -> 返回学习方向建议
```

示例回复：

```text
从最近的作答看，你下一步适合继续练异分母分数加法，重点检查通分步骤。
准备好后点击“下一题”，系统会按这个方向选择题目。
```

## 20. 提交答案流程

`answer_submitted`不进入回答上下文链：

```text
接收答案
  -> 内容仓库补齐标准答案和题目元数据
  -> 确定性判题
  -> 保存 LearningEvent
  -> 更新 KT
  -> 编译 TeachingState
  -> 保存最小审计 Trace
  -> 返回提交结果
```

这一步不做：

```text
不查询 Graphiti。
不查询 RAG。
不读取当前对话。
不调用 LLMLingua。
不组装 ResponseContextPackage。
不调用推荐器。
不切换当前题。
不生成教学讲解。
```

提交后的事实可以异步进入记忆原料系统，但不能在提交请求中直接形成长期画像。

## 21. 消费方约束

### TeachingPlanner

只读取：

```text
AssembledContext.normalized_context
AssembledContext.authoritative_kt_facts
AssembledContext.evidence_gaps
```

移除直接传入的原始 `rag_context`。

### Recommender

只读取 `selection`阶段上下文和题库摘要，不直接调用 SAFKT、Graphiti、Memory 或 RAG。
候选题的 SAFKT 概率由 `CandidateKTScorer` 在上下文构建前批量计算并作为只读字段传入。

### ResponseGenerator

只读取 `response`阶段的 `ResponseContextPackage`。

### Runtime Tool Registry

工具 Observation（观察记录）只用于审计本轮使用了什么，不重新执行第二次检索。

## 22. Evidence Gap（证据缺口）

统一缺口类型：

```text
missing_current_question
missing_grading_result
missing_teaching_state
missing_conversation
missing_student_memory
missing_rag_citation
question_concept_mismatch
context_budget
hard_budget_exceeded
compression_failed
compression_integrity_failed
graphiti_unavailable
graphiti_query_failed
provider_timeout
provider_auth_error
```

每条缺口必须包含：

```text
gap_type
reason
impact
severity
recoverable
source
stage
```

缺口只能影响上下文完整程度，不能变成掌握度或判题事实。

## 24. 安全和数据隔离

必须保证：

```text
一个学生不能检索到另一个学生的记忆。
一个 conversation 不能读取另一个 conversation 的完整聊天。
Graphiti 查询必须带 student_id 范围。
RAG 查询必须校验 question_id 和 concept_id。
Provider 原始响应、Embedding（文本向量）和密钥不能进入回答包。
被删除的记忆不能进入 selected、compressed 或 omitted 的内容摘要。
被禁用的记忆只在专家审计中显示排除原因。
```

Graphiti 凭据和压缩模型配置只能从环境变量读取。

## 25. 配置和降级

默认本地运行：

```text
MATHTUTOR_LONG_TERM_CONTEXT_BACKEND=local
MATHTUTOR_CONTEXT_COMPRESSOR=none
```

完整运行：

```text
MATHTUTOR_LONG_TERM_CONTEXT_BACKEND=graphiti
MATHTUTOR_CONTEXT_COMPRESSOR=llmlingua
```

降级规则：

```text
Graphiti 不可用 -> 使用本地长期记忆存储。
LLMLingua 不可用 -> 使用原始摘要和规则裁剪。
RAG 不可用 -> 记录缺口，不生成假引用。
对话存储不可用 -> 当前轮仍可回答，但记录 missing_conversation。
KT 不可用 -> 不允许记忆或 RAG 伪造 KT 结论。
SAFKT 模型、映射或产物不可用 -> KT 相关选题停止；不能伪装成冷启动或规则推荐。
```

任何可选 Provider 失败都不能阻断判题和学习事实保存。

## 28. 测试与验收

### 28.1 场景测试

必须覆盖：

```text
闲聊不查询 KT、Graphiti 和 RAG。
概念问题只在需要时查询 RAG。
当前题求助只能拿到当前题相关解析。
追问错因不能把 RAG 常见错误当成本次确定错因。
下一步建议不调用推荐器、不修改当前题。
点击下一题先组装选题包，选题后才查询解析。
推荐原因读取当时证据，不重新选题。
提交答案不生成回答上下文、不查询记忆和 RAG、不自动推荐。
```

### 28.2 对话隔离测试

```text
同一 conversation 可以读取最近 3～5 轮。
新 conversation 不能读取旧 conversation 全文。
新 conversation 仍能读取当前题、KT 和长期画像。
不同 student_id 之间完全隔离。
```

### 28.3 权威边界测试

```text
Graphiti 中伪造的 mastery 不能进入 authoritative_kt_facts。
RAG 和长期记忆不能覆盖判题结果。
上下文资产不能修改 KT progress。
LLMLingua 不能压缩 KT、题干和学生答案。
```

### 28.4 Graphiti 测试

```text
Graphiti 查询强制带 student_id。
过期关系不会作为当前偏好使用。
旧关系仍保留来源和有效时间。
Provider 失败会回退本地存储。
未经 MemoryRefinery 审核的候选不会写入 Graphiti。
```

### 28.5 压缩测试

```text
低于阈值不调用 LLMLingua。
只有 compressible 资产进入压缩器。
压缩前后引用编号、数字、单位和数学符号一致。
完整性检查失败时回退原始摘要。
压缩不会改变 selected asset 的来源引用。
```

### 28.6 指标

```text
无关 evidence 误入率。
必须证据遗漏率。
上下文平均 Token 数和压缩比例。
Graphiti 查询命中率和降级率。
RAG 引用准确率。
跨 conversation 泄漏数量。
KT 权威边界违规数量。
不同意图的工具误调用率。
```

验收要求：

```text
跨学生和跨 conversation 泄漏为 0。
KT 权威边界违规为 0。
没有资料时伪造引用为 0。
提交答案误调用 Memory/RAG/推荐器为 0。
下一步建议误切题为 0。
```

## 29. 参考技术与吸收边界

### Adaptive-RAG

吸收：根据问题复杂度决定不检索、单次检索或多步检索。

在本项目中改为确定性的教学场景策略，不让分类器自由决定是否读取 KT 权威事实。

参考：<https://arxiv.org/abs/2403.14403>

### RECOMP

吸收：检索后压缩、选择性增强、无相关内容时允许不提供检索上下文。

参考：<https://arxiv.org/abs/2310.04408>

### MemGPT / Letta

吸收：当前上下文和外部长期记忆分层、按需调入。

不照搬：让第二套 Agent Runtime 接管 MathTutor 的判题、KT、推荐和上下文编排。

参考：<https://arxiv.org/abs/2310.08560>

### Graphiti

吸收：时间关系、事实有效期、来源追踪和历史替代。

限制：只保存经过证据审核的长期关系，不保存 KT 权威事实。

参考：<https://github.com/getzep/graphiti>

### LLMLingua

吸收：面向长上下文的软证据压缩和结构化片段保护。

限制：数学条件、正式事实和引用字段不可压缩。

参考：<https://github.com/microsoft/LLMLingua>

### Lost in the Middle

吸收：长上下文会降低关键信息利用率，因此不能通过“全部塞入”解决上下文问题。

参考：<https://arxiv.org/abs/2307.03172>

## 30. 最终结论

MathTutor 的上下文模块不是一个简单的 Prompt（提示词）拼接器。

正确实现是：

```text
系统事件和聊天意图先分开；
ContextPolicy 决定这一轮查什么；
LearningContextLayer 统一读取、选择、压缩和组装；
当前对话按 conversation_id 隔离；
Graphiti 保存经过审核的长期关系记忆；
LLMLingua 只压缩允许压缩的软证据；
点击下一题走选题包和回答包两阶段；
提交答案只更新事实和 KT，不进入回答上下文；
所有消费方只能读取治理后的上下文包；
任何记忆、RAG、压缩结果和 LLM 输出都不能覆盖 KT 权威事实。
```

最终要达到的效果：

```text
该查的才查。
该带的才带。
重要事实不会被裁掉。
软证据可以压缩。
长期关系可以随时间演进。
所有内容都能说明来源、选择原因和缺失原因。
```
