# 判题与作答证据模块开发设计

> 状态：设计完成，待开发。

## 1. 文档目的

本文设计 MathTutor Agent 的正式判题与作答证据模块。

模块要把一次“点击提交答案”转换为稳定、可审计、可幂等处理的学习事实，并明确这次作答是否有资格进入知识追踪。

本文同时给出：

```text
第一阶段：贴合当前仓库、可以直接开发的最小版本。
第二阶段：题型增加后再演进的目标结构。
```

本设计吸收了 `重构思考/完整流程预演.md` 和 `重构思考/思考链路.md` 中已经确认的规则。

---

## 2. 一句话定义

```text
判题与作答证据模块接收一次正式提交，读取题目答案规格和提交前题目状态，
完成答案归一化、确定性比较和证据资格判断，
返回版本化、可追溯且不能被 LLM 改写的 AnswerAssessmentResult。
```

职责分工：

```text
题库模块：提供题目和 AnswerSpec。
本模块：判断本次提交是什么、是否正确、证据是否可用于 KT。
学习事实模块：持久化提交、判题和查看答案事实。
KT 模块：只消费 eligible_for_kt=true 的正式结果。
TeachingState：整理判题事实和 KT 结果。
Agent / RAG / Memory：只读结果，不能重新判题或覆盖结果。
```

---

## 3. 现状盘点

### 3.1 当前已有能力

当前仓库已经具备最小判题链路：

```text
POST /api/events
  → LearningEvent(type=answer_submitted)
  → MathTutorLearningLoop._grade_answer_if_needed
  → ContentRepository.grade
  → 回填 is_correct、correct_answer、grading_source
```

`BaseTeachingContentRepository.grade()` 当前会：

```text
去除首尾空白。
移除普通空格。
把中文逗号转换为英文逗号。
转成小写。
按归一化后的字符串完全相等判题。
```

当前也有一层重复提交保护：近期事件中相同 `question_id + answer` 且已经判题的提交，不重复更新 mastery。

### 3.2 当前主要缺口

当前实现不能直接作为正式判题契约，原因如下：

```text
1. 判题逻辑位于 ContentRepository，题目读取和答案比较职责混在一起。
2. 只支持字符串相等，1/2、0.5、2/4 会被视为不同答案。
3. 判题结果被写回通用 payload，没有独立、版本化的正式结果模型。
4. 缺少 submission_id，幂等依赖最近 20 条事件和原始答案字符串。
5. 没有 answer_revealed 事件，无法判断提交前是否看过答案。
6. 没有区分“判题成功”和“证据可进入 KT”。
7. 缺少归一化过程、比较方法、答案来源和规则版本等审计信息。
8. answer_submission 当前仍会进入 RAG、Memory、Planner 和推荐链路。
9. 错误提交当前可能自动生成讲解、写 Memory、推荐下一题。
10. 缺少步骤证据结构，无法保留学生中间过程。
```

因此，本次开发不能只扩展 `_normalize_answer()`。需要先建立正式提交和正式判题结果契约。

## 4. 已确定的设计原则

### 4.1 正式提交只能由提交动作产生

以下动作可以产生正式提交：

```text
学生在题目区域点击“提交答案”。
客户端生成 submission_id。
服务端收到 SubmitAnswerCommand。
```

以下内容不能产生正式提交：

```text
学生在 Agent 聊天框里说“答案是不是 3/4”。
Agent 从对话中猜测学生已经完成作答。
LLM 从图片、草稿或上下文中抽取出的候选答案。
页面自动保存的输入框草稿。
```

聊天里的答案只能作为对话草稿或步骤讨论，不能写 `grading_result`，不能更新 KT。

### 4.2 正式正确性只由确定性规则产生

第一阶段的正式判题不调用 LLM，不调用 RAG，不读取 Memory。

```text
LLM 可以解释已有判题结果。
LLM 可以讨论非正式草稿。
LLM 不能生成或修改 is_correct。
LLM 不能把 unknown 改成 correct / incorrect。
```

### 4.3 判题成功不等于证据可用于 KT

例如，学生提交前已经查看标准答案：

```text
仍然可以确定性判题。
仍然保存提交和判题事实。
但 eligible_for_kt=false。
不更新 mastery。
不推进正式学习阶段。
```

### 4.4 判题结果不可原地改写

已经完成的 `GradingResult` 是不可变事实。

答案规则发生变化时，必须创建新的结果版本，并记录：

```text
supersedes_grading_id
grading_rule_version
answer_spec_version
regrade_reason
```

历史结果不得静默覆盖。

### 4.5 不确定时显式返回 unknown

没有标准答案、题型不支持、题型内答案格式非法或比较器失败时，不允许猜测。

```text
grading_status = ungradable | invalid | failed
decision = unknown
eligible_for_kt = false
```

空答案、超长答案和步骤数量超限属于命令校验失败。它们在生成正式提交事实之前被拒绝。

## 5. 模块边界

### 5.1 模块负责

```text
校验与判题相关的答案和规格约束。
保留学生原始答案。
按题型归一化答案。
使用确定性比较器判题。
提取可验证的步骤证据。
判断证据是否可进入 KT。
返回 AnswerSubmission、GradingResult、AnswerEvidence 和 EvidenceEligibility。
记录规则版本、答案来源和证据缺口。
```

### 5.2 模块不负责

```text
不负责选择当前题。
不负责 submission_id 幂等和并发控制。
不负责数据库表、事务和事实恢复。
不负责发布 outbox 或领域事件。
不负责调用或等待 KT。
不负责推荐下一题。
不负责更新 mastery。
不负责生成教学解释。
不负责检索知识资料。
不负责写长期学生画像。
不负责判断开放证明题的语义正确性。
不负责从聊天内容自动创建正式提交。
不负责在线训练判题模型。
```

### 5.3 权威关系

```text
题目标准：AnswerSpec 权威。
学生提交内容：AnswerSubmission.raw_answer 权威。
正确性：GradingResult 权威。
是否看过答案：AnswerRevealFact 权威。
是否进入 KT：EvidenceEligibility 权威。
掌握度：TeachingState / KT 权威。
解释文本：RAG / Agent 只提供教学表达，不是学习事实。
```

### 5.4 判题结果与 KT 结果如何同时使用

判题和 KT 回答的是不同问题，不允许互相覆盖：

```text
GradingResult：学生这一次提交答对了吗？
TeachingState：学生对相关知识点整体掌握得怎么样？
```

允许同时出现：

```text
本次答对 + mastery=0.42：这次做对了，但整体掌握仍不稳定。
本次答错 + mastery=0.85：这次做错了，但历史上整体掌握较好。
```

回复“刚才答对了吗”只能读取 `GradingResult`。回复“这个知识点掌握得怎么样”只能读取 `TeachingState`。

KT 不得因为掌握度高而把本次错误改成正确；判题模块也不得因为本次答错而直接把整体掌握度改成低。

## 6. 核心术语

| 术语 | 含义 |
|---|---|
| `AnswerSpec` | 题目的版本化答案规格，包括题型、标准值、容差和比较规则。 |
| `AnswerSubmission` | 学生点击提交后产生的不可变原始提交事实。 |
| `GradingResult` | 确定性比较后生成的正式判题结果。 |
| `AnswerEvidence` | 支撑判题和后续诊断的归一化值、步骤、来源及缺口。 |
| `AnswerRevealFact` | 学生通过页面查看答案产生的事实。 |
| `EvidenceEligibility` | 本次判题结果是否有资格进入 KT，以及原因。 |
| `AnswerAssessmentResult` | 本模块返回的作答、判题、证据和资格结果。 |
| `formal submission` | 由提交按钮触发、具有 submission_id 的正式提交。 |
| `draft answer` | 聊天或输入框中的非正式尝试，不产生正式判题事实。 |

---

### 6.1 统一事件名称

```text
提交命令：SubmitAnswerCommand
保存事实：AnswerSubmission
允许进入 KT 的领域事件：formal_answer_recorded
查看答案命令：RevealAnswerCommand
查看答案事实和事件：AnswerRevealFact / answer_revealed
```

`answer_submitted` 是旧 `/api/events` 的兼容事件名；`answer_submission` 是旧 Runtime capability 名称。新模块不再把它们作为正式领域事件名。

## 7. 对外接口

模块对外只暴露一个评估接口：

```python
class AnswerAssessment:
    def assess(self, request: AnswerAssessmentRequest) -> AnswerAssessmentResult:
        ...
```

调用方不需要知道使用哪个归一化器、比较器或证据提取器。

模块内部可以按题型拆分实现，但这些不是调用方接口。

### 7.1 AnswerAssessmentRequest

```python
class AnswerAssessmentRequest(BaseModel):
    command: SubmitAnswerCommand
    question: dict[str, object]
    answer_spec: AnswerSpec
    reveal_fact: AnswerRevealFact | None = None
    question_state_version: int
    attempt_number: int
    prior_eligible_attempt_exists: bool
```

字段约束：

```text
command：上层已经完成基础格式校验的正式提交命令。
answer_spec：题库模块提供的版本化答案规则。
reveal_fact：学习事实模块提供的提交前查看答案事实。
question_state_version：上层确认后的当前题状态版本。
attempt_number：事实账本计算的当前题尝试次数。
prior_eligible_attempt_exists：同一题目状态是否已有合格 KT 作答。
```

客户端不能提交：

```text
is_correct
correct_answer
grading_status
eligible_for_kt
answer_revealed_before_submit
```

这些字段只能由服务端产生。

### 7.2 AnswerAssessmentResult

```python
class AnswerAssessmentResult(BaseModel):
    submission: AnswerSubmission
    grading: GradingResult
    evidence: AnswerEvidence
    eligibility: EvidenceEligibility
```

该结果不包含数据库保存状态、网络重放状态、KT 执行状态或 TeachingState 引用。这些属于学习事实与运行编排模块。

## 8. 数据模型

### 8.1 AnswerSpec

当前题库只有 `standard_answer: str`。第一阶段需要增加可版本化答案规格，并提供旧字段适配器。

```python
class AnswerSpec(BaseModel):
    question_id: str
    version: str
    answer_type: Literal[
        "exact_text",
        "single_choice",
        "multiple_choice",
        "integer",
        "decimal",
        "rational",
    ]
    canonical_answer: str
    accepted_answers: list[str] = Field(default_factory=list)
    case_sensitive: bool = False
    order_sensitive: bool = True
    absolute_tolerance: str | None = None
    normalizer_version: str
    comparator_version: str
    provenance: dict[str, object] = Field(default_factory=dict)
```

第一阶段不支持：

```text
通用代数表达式等价。
方程组解集等价。
区间和集合表达式等价。
带物理量单位自动换算。
几何证明、过程题和开放题自动满分判定。
```

这些题型没有比较器时返回 `unsupported_answer_type`，不使用字符串相等冒充正确判题。

### 8.2 AnswerSubmission

```python
class AnswerSubmission(BaseModel):
    submission_id: str
    student_id: str
    session_id: str
    question_id: str
    raw_answer: str
    raw_steps: list[str] = Field(default_factory=list)
    submitted_at: str
    question_state_version: int
    attempt_number: int
    answer_spec_version: str | None = None
```

该对象只记录“学生提交了什么”，不混入判题结果。

### 8.3 GradingResult

```python
class GradingResult(BaseModel):
    grading_id: str
    submission_id: str
    question_id: str
    status: Literal["succeeded", "ungradable", "invalid", "failed"]
    decision: Literal["correct", "incorrect", "unknown"]
    is_correct: bool | None
    normalized_answer: str | None
    normalized_expected_answers: list[str]
    matched_expected_answer: str | None
    comparison_method: str | None
    grading_rule_version: str
    answer_spec_version: str | None
    grading_source: str
    created_at: str
    reason_code: str | None = None
```

不变量：

```text
status=succeeded 时，is_correct 必须是 true 或 false。
status!=succeeded 时，decision=unknown 且 is_correct=null。
decision=correct 时，matched_expected_answer 不能为空。
```

### 8.4 AnswerEvidence

```python
class AnswerEvidence(BaseModel):
    evidence_id: str
    submission_id: str
    grading_id: str
    answer_type: str | None
    normalization_steps: list[dict[str, str]]
    comparison_evidence: dict[str, object]
    step_evidence: list[StepEvidence]
    provenance: dict[str, object]
    evidence_gaps: list[EvidenceGap]
```

`normalization_steps` 只保存可审计摘要，例如：

```json
[
  {"operation": "trim", "before": " 2/4 ", "after": "2/4"},
  {"operation": "reduce_fraction", "before": "2/4", "after": "1/2"}
]
```

不得在学生可见回复中直接暴露全部内部调试信息。

### 8.5 StepEvidence

第一阶段只提取确定性、可验证的步骤证据。

```python
class StepEvidence(BaseModel):
    step_index: int
    raw_step: str
    normalized_step: str | None
    status: Literal["recorded", "parseable", "unparseable"]
    claims: list[dict[str, object]] = Field(default_factory=list)
```

第一阶段不根据步骤自动给部分分，也不让 LLM 生成正式错因。

步骤证据的用途是：

```text
保留学生真实过程。
为后续“为什么错”提供可引用输入。
为未来确定性步骤检查保留扩展位置。
```

### 8.6 EvidenceEligibility

```python
class EvidenceEligibility(BaseModel):
    submission_id: str
    eligible_for_kt: bool
    evidence_kind: Literal[
        "independent_attempt",
        "after_answer_reveal",
        "repeated_attempt_same_question_state",
        "ungraded_attempt",
        "invalid_attempt",
    ]
    reason_codes: list[str]
    reveal_fact_id: str | None = None
```

进入 KT 必须满足全部条件：

```text
正式提交命令有效。
grading.status == succeeded。
 is_correct 是明确布尔值。
 提交前没有查看答案。
 题目和知识点映射满足 KT 要求。
```

`submission_id` 是否已经被 KT 消费属于分发幂等状态，不改变本次作答原有的证据资格。

## 9. 第一阶段支持的归一化与比较

第一阶段优先使用 Python 标准库，不新增符号计算依赖。

### 9.1 通用预处理

所有题型先执行：

```text
保留 raw_answer 原文。
去除首尾空白。
统一全角和半角逗号。
统一常见 Unicode 负号为 ASCII `-`。
按 AnswerSpec 决定是否忽略大小写。
拒绝空答案。
限制答案长度和步骤数量。
```

不能做会改变数学语义的全局替换。

例如，不能对所有题型直接删除全部空格，因为文本答案中的空格可能有意义。

### 9.2 exact_text

规则：

```text
只做 AnswerSpec 明确允许的大小写和首尾空白处理。
与 canonical_answer 和 accepted_answers 逐一比较。
```

### 9.3 single_choice

规则：

```text
接受 A、a、Ａ 等可配置形式。
归一化为大写选项编号。
只允许一个有效选项。
```

### 9.4 multiple_choice

规则：

```text
解析 A,C、AC、A C 等形式。
去重并校验选项范围。
order_sensitive=false 时按集合比较。
```

### 9.5 integer

使用 Python `int` 做严格解析。

```text
允许前导正号和前导零。
拒绝小数、科学计数法和混入单位的字符串。
```

### 9.6 decimal

使用 `decimal.Decimal`，不使用二进制浮点直接比较。

```text
无容差时比较精确数值。
有 absolute_tolerance 时比较绝对误差。
不默认设置容差。
```

### 9.7 rational

使用 `fractions.Fraction`。

```text
1/2、2/4、0.5 可以归一化为相同有理数。
分母为 0 时返回 invalid_answer_format。
```

是否允许小数输入由 `AnswerSpec` 明确配置，不能所有分数题默认接受近似小数。

## 10. 判题状态与原因码

### 10.1 状态定义

| status | decision | 含义 |
|---|---|---|
| `succeeded` | `correct` / `incorrect` | 已使用确定性规则完成判题。 |
| `ungradable` | `unknown` | 题目缺少答案规格或题型暂不支持。 |
| `invalid` | `unknown` | 命令已通过基础校验，但答案不符合该题型的数学格式。 |
| `failed` | `unknown` | 模块内部异常或依赖读取失败。 |

### 10.2 第一阶段原因码

```text
missing_question_id
question_not_found
stale_question_state
missing_answer_spec
unsupported_answer_type
empty_answer
answer_too_long
too_many_steps
invalid_answer_format
invalid_choice
zero_denominator
comparison_failed
answer_revealed_before_submit
missing_kt_mapping
duplicate_submission
repeated_attempt_same_question_state
```

原因码用于程序分支、测试和统计；学生提示由上层根据原因码映射，不能把内部异常原文直接返回前端。

## 11. 提交流程

### 11.1 正常独立作答

```text
收到 AnswerAssessmentRequest
  → 校验答案规格和作答内容
  → 构造 AnswerSubmission
  → 按 answer_type 归一化
  → 确定性比较
  → 生成 GradingResult
  → 生成 AnswerEvidence
  → 计算 EvidenceEligibility
  → 返回 AnswerAssessmentResult
```

本模块到返回评估结果为止，不继续执行其他链路：

```text
不查 RAG。
不查 Memory。
不生成错因讲解。
不推荐下一题。
不自动写长期画像。
不进入 Agent 对话。
```

### 11.2 提交前已经查看答案

```text
AnswerRevealFact.reveal_timing = before_submit
  → 正常生成 AnswerSubmission
  → 正常确定性判题
  → evidence_kind = after_answer_reveal
  → eligible_for_kt = false
  → 不更新 mastery
```

### 11.3 提交后查看答案

提交时尚未查看答案，则本次独立作答资格已经确定。

后续发生 `answer_revealed`：

```text
reveal_timing = after_submit
```

该事件不能反向修改本次 `eligible_for_kt=true` 的结果。

### 11.4 重复请求与重复尝试

同一 `submission_id` 的网络重放由学习事实模块处理，不再次调用本模块。

```text
学习事实模块读取原保存结果。
上层返回 replayed=true。
不重新执行 AnswerAssessment.assess()。
```

相同题目、相同答案但新的 `submission_id` 不应自动视为网络重试。

新的 `submission_id` 是新的正式尝试。本模块根据 `prior_eligible_attempt_exists` 判断证据资格。

```text
第一次未看答案且判题成功：eligible_for_kt=true。
同一题目状态下的后续提交：保存和判题，但 eligible_for_kt=false。
后续提交的 evidence_kind=repeated_attempt_same_question_state。
重新布置题目或题目状态版本变化后，可以重新产生一次 KT 证据。
```

这样可以保留真实练习过程，又避免反复尝试同一道题把 KT 历史刷偏。

### 11.5 无法判题

本节只适用于题目真实存在，但答案规格缺失、题型暂不支持或题型内答案格式非法的情况。

```text
生成 AnswerSubmission。
生成 decision=unknown 的 GradingResult。
记录 evidence_gap。
eligible_for_kt=false。
返回 decision=unknown 的 AnswerAssessmentResult。
```

本模块不能把“无法判题”当成“回答错误”。结果是否保存以及如何返回状态提示由上层负责。

题目不存在或当前题状态版本冲突属于提交前置条件失败，分别返回 404 或 409，不创建正式作答事实。

---

## 12. 查看答案事实

`answer_revealed` 由页面“查看答案”按钮产生，属于学习事实模块。

本模块只读取该事实，不根据前端布尔值判断。

建议模型：

```python
class AnswerRevealFact(BaseModel):
    reveal_id: str
    student_id: str
    session_id: str
    question_id: str
    question_state_version: int
    answer_submitted_before_reveal: bool
    reveal_timing: Literal["before_submit", "after_submit"]
    revealed_at: str
```

不变量：

```text
查看答案不等于答错。
查看答案不等于掌握。
查看答案本身不更新 KT。
提交前查看答案会使后续提交失去独立作答资格。
提交后查看答案不反向改变已完成的独立作答资格。
```

---

## 13. 持久化边界

本模块不拥有数据库表、事务、outbox 或恢复逻辑。

```text
输入：AnswerAssessmentRequest。
输出：AnswerAssessmentResult。
```

学习事实模块负责保存结果、处理 `submission_id` 幂等、发布 `formal_answer_recorded`，并协调 KT。详细设计见《学习事实与题目状态模块开发设计》。

## 14. 模块联动

只保留以下输入输出关系：

| 模块 | 与本模块的关系 |
|---|---|
| 题库模块 | 提供 `Question` 和版本化 `AnswerSpec`。 |
| 学习事实模块 | 提供题目状态、查看答案事实和历史尝试；保存本模块返回结果。 |
| KT 模块 | 由学习事实模块根据 `EvidenceEligibility` 决定是否发布事件，本模块不直接调用 KT。 |
| Agent / RAG | 后续只读 `GradingResult` 和 `AnswerEvidence` 进行讲解。 |
| 记忆模块 | 后台读取已保存事实；本模块不调用 Memory 或 HMS。 |
| TeachingTrace | 由上层记录结果引用，本模块不负责保存 Trace。 |

禁止：

```text
判题模块直接写数据库或 outbox。
判题模块直接更新 KT 或 mastery。
判题模块直接写 StudentMemory 或 HMS。
判题模块直接调用 RAG、Planner 或推荐器。
```

## 17. 安全与隐私

```text
限制 raw_answer 长度，例如 4 KB。

不执行学生输入中的代码。
不把学生输入拼接进 SQL。
```

若未来接入 LaTeX 或符号计算，必须把解析器当作不可信输入边界，并增加超时、节点数和表达式深度限制。

## 19. 分阶段开发

### Phase 1：建立正式契约

```text
新增 grading 数据模型。
把现有 standard_answer 适配为 exact_text AnswerSpec。
实现 AnswerAssessment.assess()。
把判题算法从 LearningLoop 移入本模块。
```

验收：相同评估输入返回稳定 GradingResult，不再依赖通用 payload 作为正式契约。

### Phase 2：补齐答案查看和证据资格

```text
在 AnswerAssessmentRequest 中接收上层提供的 AnswerRevealFact。
输出 EvidenceEligibility。
```

验收：提交前看答案不会更新 mastery，提交后看答案不会反向污染已有正式作答。

### Phase 3：扩展基础数学题型

```text
支持 single_choice、multiple_choice、integer、decimal、rational。
使用 Decimal 和 Fraction。
加入版本化 normalizer / comparator。
```

验收：`1/2`、`2/4` 和按规格允许的 `0.5` 能稳定按数学值比较。

### Phase 4：切断自动教学副作用

```text
SubmitAnswerCommand 不进入通用 Agent Runtime。
不自动 RAG、Memory、Planner、推荐或讲解。
后续教学由新的用户 intent 单独触发。
```

验收：提交接口的依赖调用中不出现上述教学模块。

### Phase 5：步骤证据

```text
保存结构化 raw_steps。
增加确定性步骤归一化和可解析状态。
在“为什么错”流程中引用步骤证据。
```

验收：步骤证据可追溯，但不会在没有正式规则时自动给部分分或创造错因。

### Phase 6：按需求增加高级比较器

出现真实题目需求后再评估：

```text
SymPy 表达式等价。
集合与区间。
方程和方程组。
单位与量纲。
人工复核或教师评分。
```

每新增一种比较器，都必须先定义 AnswerSpec、资源限制、失败语义和测试语料。

## 20. 从现有代码迁移

| 当前实现 | 迁移目标 |
|---|---|
| `ContentRepository.grade()` | 题库只提供 AnswerSpec；判题移入 `AnswerAssessment`。 |
| `_normalize_answer()` | 拆为按 answer_type 选择的内部归一化函数。 |

| `standard_answer: str` | 通过 Adapter 生成第一版 `AnswerSpec`。 |
| 自动写 Memory / 推荐下一题 | 本模块不再依赖这些能力。 |

兼容期内，上层可以把 `AnswerAssessmentResult` 投影回旧 `LearningEvent.payload`，但本模块不读写该 payload。

## 21. 验收标准

模块完成时必须满足：

```text
1. 原始答案、归一化答案和正式结果分开返回。
2. 判题结果包含答案规格版本和规则版本。

6. 本模块不访问数据库，不发布事件，不调用 KT。
7. 本模块不调用 LLM、RAG、Memory、HMS、Planner 和推荐器。
8. 后续模块可以通过 submission、grading 和 evidence 引用追溯结果。
9. 现有 demo 答案可通过 AnswerSpec Adapter 继续评估。
10. 所有失败都有稳定 reason_code 和可测试行为。
```

## 22. 最终边界总结

```text
学生提交了什么：认 AnswerSubmission。
答案标准是什么：认 AnswerSpec。
这次答对没有：认 GradingResult。
这次是否独立作答：认 AnswerRevealFact + EvidenceEligibility。
这次能否进入知识追踪：认 eligible_for_kt。
学生是否掌握：认 KT / TeachingState，不认单次判题。
为什么错、接下来怎么讲：由教学模块读取上述事实后决定。
```

本模块的核心不是“多写几个答案比较函数”，而是建立一条不会被聊天、模型输出和重复请求污染的正式学习证据链。
