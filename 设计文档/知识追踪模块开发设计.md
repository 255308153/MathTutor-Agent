# 知识追踪模块开发设计

## 1. 文档目的

本文说明 MathTutor Agent 的知识追踪模块如何从现有状态改造成一条可以真实运行的 SAFKT-V2 链路。

当前阶段的重点是：

```text
先让 XES3G5M 作答历史能够经过真实模型推理，
生成可信、可追踪的 TeachingState，
再交给教学和推荐模块使用。
```

本阶段不以论文实验和模型横向对比为主，不建设完整实验平台，不追求一次完成所有高级解释能力。

---

## 2. 一句话定义

```text
知识追踪模块读取学生可靠的正式作答历史，
使用 SAFKT-V2 估计目标题答对概率、相关知识点状态和遗忘信号，
再编译成本轮教学可以只读使用的 TeachingState。
```

职责分工：

```text
判题模块：学生这次答对还是答错。
SAFKT-V2：根据历史估计学生接下来会不会。
TeachingStateCompiler：把模型输出和判题事实整理成教学状态。
教学规划模块：根据教学状态决定怎么教。
推荐模块：根据教学状态决定下一题选什么方向。
```

---

## 3. 已确定的技术决策

### 3.1 正式运行只使用 SAFKT-V2

正式链路只有一个知识追踪引擎：

```text
engine_name = safkt
model_family = SAFKT-V2
```

不做以下运行时降级：

```text
不降级到 DGEKT。
不降级到 mock（模拟引擎）。
不使用启发式概率冒充 SAFKT 输出。
不使用上一份状态冒充本轮新状态。
```

`mock` 只允许出现在单元测试中，用于验证调用方，不允许出现在正式配置和正式 Trace（教学追踪记录）中。

### 3.2 正式数据使用 XES3G5M

XES3G5M 当前可用事实：

```text
有效题目数：7652
叶子知识点数：1175
单题最多关联知识点数：6
序列长度：官方预处理文件按 200 截断
时间信息：毫秒级 timestamp（时间戳）
```

现有 SAFKT checkpoint（模型参数文件）来自 ASSIST2017，输出空间固定为 3162 道题，不能用于 XES3G5M 正式教学。

因此必须使用 XES3G5M 重新训练 SAFKT-V2。

### 3.3 pyKT 只作离线参考

`pyKT` 是基于 PyTorch 的知识追踪训练和评测工具箱，提供数据预处理、训练循环、模型实现和评测方法。

本项目对它的使用方式是：

```text
可以参考 pyKT 的 XES3G5M 数据读取、时间特征和评测口径。
可以在离线阶段用 pyKT 检查数据格式或结果。
MathTutor Agent 线上运行不依赖 pyKT。
SAFKT-V2 正式推理只依赖 PyTorch 和导出的模型产物。
```

### 3.4 模型不在线训练

学生每次提交答案后，系统只做在线推理，不立刻更新神经网络参数。

```text
在线更新 = 新作答进入学生历史，再重新推理。
在线更新 != 现场训练模型参数。
```

模型参数只在离线训练流程中更新和发布。

## 4. 模块边界

### 4.1 模块负责

```text
读取可用于知识追踪的正式作答历史。
校验题目和知识点映射。
构造 SAFKT-V2 推理输入。
执行真实模型推理。
输出目标题答对概率。
输出真实时间相关的遗忘信号。
输出关键历史信号。
整理相关知识点掌握度估计。
生成带版本和证据状态的 TeachingState。
记录模型输入摘要、版本和失败阶段。
```

### 4.2 模块不负责

```text
不负责确定性判题。
不负责解析学生自然语言答案。
不直接判断计算错误、审题错误等具体错因。
不负责检索 RAG（检索增强生成）资料。
不写长期学生画像。
不决定最终教学话术。
不直接选择下一道题。
不训练或微调大语言模型。
```

## 5. 哪些事件可以更新知识追踪

只有满足全部条件的正式作答才能进入 SAFKT 历史：

```text
event.type == answer_submitted
answer_viewed == false
grading_status == succeeded
is_correct 是明确的 true 或 false
question_id 和 concept_ids 映射完整
submission_id 尚未处理过
```

以下行为只保存为学习事实，不进入 SAFKT 正式作答序列：

```text
选择学习目标
自报接触过某知识点
选择初次学习、复习或正在练习
查看答案
跳过题目
换题
请求提示
询问 Agent
```

幂等规则：

```text
同一个 submission_id 最多进入一次正式作答历史。
重复请求可以返回已有处理结果，但不能再次更新状态。
```

## 6. 总体结构

```text
正式作答事件
  → 判题模块
  → 保存作答事实
  → SAFKTInputBuilder（推理输入构造器）
  → SAFKTEngine（SAFKT 推理引擎）
  → SAFKTOutput（原始模型结果）
  → TeachingStateCompiler（教学状态编译器）
  → TeachingState（教学状态快照）
  → Context / 教学规划 / 推荐 / Trace 只读使用
```

模型原始张量不得直接进入大语言模型上下文。

## 8. XES3G5M 数据输入

### 8.1 数据来源

第一版使用题目级序列：

```text
XES3G5M/question_level/train_valid_sequences_quelevel.csv
XES3G5M/question_level/test_quelevel.csv
XES3G5M/metadata/questions.json
XES3G5M/metadata/kc_routes_map.json
```

题目级文件中的多个知识点使用下划线分隔，例如：

```text
66_11_17_326
```

不能把它解析成一个巨大的知识点编号，必须解析为四个知识点。

### 8.2 单个批次结构

```python
SAFKTBatch:
    question_ids       # [B, 200]
    concept_ids        # [B, 200, 6]
    responses          # [B, 200]
    timestamps         # [B, 200]
    response_gaps      # [B, 200]
    concept_gaps       # [B, 200, 6]
    practice_counts    # [B, 200, 6]
    valid_mask         # [B, 200]
```

说明：

```text
B：一个训练批次中的序列数量。
200：当前统一历史长度。
6：一道题最多关联的知识点数量。
-1：数据文件中的补位值，不是合法题目或知识点。
```

### 8.3 模型内部编号

XES3G5M 题目和知识点编号可以从 0 开始，但神经网络内部需要为补位预留编号 0：

```text
模型题目编号 = XES3G5M 题目编号 + 1
模型知识点编号 = XES3G5M 知识点编号 + 1
模型编号 0 = padding（补位）
```

这个偏移只存在于模型内部。Agent、数据库和 Trace 继续使用规范编号，例如：

```text
xes3g5m:128
```

### 8.4 时间特征

需要计算三类特征：

```text
response_gap：距离上一次任意正式作答的时间。
concept_gap：距离上次练习同一知识点的时间。
practice_count：该知识点此前的正式练习次数。
```

时间戳单位统一为毫秒，进入模型前转为分钟或小时，再进行对数分桶：

```python
gap_bucket = floor(log2(1 + gap_minutes))
count_bucket = floor(log2(1 + practice_count))
```

第一条历史没有上一次作答，使用专门的 `unknown_gap` 分桶，不伪造为 0 分钟。

### 8.5 训练错位

历史位置 `t` 只能预测下一位置 `t+1`：

```text
输入：q0/r0, q1/r1, ..., qt/rt
目标题：q(t+1)
监督标签：r(t+1)
```

不能先把目标题的对错放入历史，再预测同一道题，否则会发生 label leakage（标签泄漏）。

线上推理同样遵守：

```text
history：已经完成判题的过去作答。
target_question_id：尚未把结果放入历史的目标题。
```

## 9. 双图构建

### 9.1 知识点超图

知识点超图表达：

```text
一道题关联哪些知识点；
哪些题因为共享知识点而相关。
```

输入来自题目与知识点映射，构图结果必须保存版本和映射摘要。

### 9.2 题目转移有向图

题目转移图表达训练数据中的顺序关系：

```text
学生完成题目 A 后继续完成题目 B
→ A 到 B 增加一条有向转移计数
```

只允许使用训练折构图，不能从验证集或测试集读取转移关系。

每道题第一版只保留权重最高的 20 条出边：

```text
transition_top_k = 20
```

### 9.3 稀疏存储

两张图必须使用 sparse tensor（稀疏张量）或稀疏边列表。

禁止先构造完整稠密矩阵。7652 道题对应的题目交互空间较大，稠密构图会造成不必要的内存占用。

## 10. SAFKT-V2 模型设计

### 10.1 输入表示

每次历史交互的输入向量由以下信息相加或拼接后投影得到：

```text
question_embedding       题目向量
concept_embedding        多知识点汇总向量
response_embedding       对错向量
response_gap_embedding   全局作答间隔向量
concept_gap_embedding    同知识点间隔向量
practice_count_embedding 练习次数向量
```

多知识点题使用 `concept_mask`（知识点遮罩）后取平均，不得只取第一个知识点。

### 10.2 主干网络

```text
题目与知识点输入
  ├── HGCN（超图卷积网络）：提取题目与知识点关系
  └── DGCN（有向图卷积网络）：提取题目转移关系
            ↓
双图特征与对错、时间特征融合
            ↓
Causal Self-Attention（因果自注意力）
            ↓
GRU（门控循环单元）
            ↓
真实时间遗忘门
            ↓
目标题预测
```

自注意力必须同时使用：

```text
causal_mask：禁止读取未来交互。
padding_mask：禁止关注补位位置。
```

### 10.3 真实时间遗忘门

旧模型使用序列位置归一化模拟时间，不足以表示真实遗忘。

SAFKT-V2 使用真实的同知识点间隔：

```python
decay_rate = softplus(decay_network(hidden_state, concept_embedding))
retention = exp(-decay_rate * log1p(concept_gap_hours))
forgotten_state = hidden_state * retention
forgetting_score = 1 - retention
```

输出含义：

```text
retention：保留程度，越高表示保留越好。
forgetting_score：遗忘信号，越高表示时间衰减越明显。
```

在没有校准数据前，文档和界面都必须称其为“遗忘信号”或“遗忘风险估计”，不能称为真实遗忘概率。

### 10.4 目标题预测

第一版只计算调用方指定目标题的概率，不一次输出全部 7652 道题：

```python
target_probability = sigmoid(
    question_head(forgotten_state, target_question_embedding)
)
```

这样既能支持当前题诊断，也能支持推荐模块对少量候选题逐批评分。

### 10.5 知识点状态输出头

第一版正式采用“SAFKT 主干网络 + 受 QIKT 启发的知识点状态输出头”。
这里只借鉴 QIKT 的多层次预测思路，不加载完整 QIKT，不运行两套模型，也不对两个模型的概率做加权平均。

对调用方指定的目标知识点逐个计算：

```python
concept_state = sigmoid(
    concept_head(forgotten_state, target_concept_embedding)
)
```

输出只覆盖当前目标题或调用方明确指定的知识点，不在每次推理时扫描全部 1175 个知识点。

每个知识点输出至少包含：

```text
concept_id
state_estimate       # 模型估计值，不是真实掌握度标签
evidence_count       # 与该知识点相关的正式作答数量
evidence_sufficiency # insufficient / limited / sufficient
source = model_estimate
```

XES3G5M 没有真实知识点掌握度标签，多知识点题的对错也不能证明具体哪个知识点掌握或未掌握。
因此 `state_estimate` 属于弱监督估计，必须连同证据数量和证据充足程度一起使用。

TeachingStateCompiler 不再使用加权正确率替代模型输出，只负责：

```text
统计证据数量；
判定证据是否充足；
在没有正式作答证据时将状态编译为 unknown；
保留模型、映射、输入和编译器版本；
不自行创造新的掌握度数值。
```

### 10.6 关键历史信号

从目标题对应的注意力权重中选择最多 5 条历史：

```text
历史题目
历史知识点
当时是否答对
距离当前多久
注意力权重
```

注意力只能说明模型重点关注了哪些历史，第一版证据状态统一为：

```text
evidence_status = partial
```

不把注意力权重描述为因果贡献。

## 11. 模型训练

### 11.1 第一版训练目标

第一版只保留目标题预测和知识点状态输出所必需的损失：

```text
主融合分支的二元交叉熵损失；
超图分支的辅助预测损失；
有向图分支的辅助预测损失。
知识点状态输出头的弱监督辅助损失。
```

初始形式：

```python
total_loss = (
    ensemble_loss
    + 0.3 * hypergraph_branch_loss
    + 0.3 * transition_branch_loss
    + 0.1 * concept_state_loss
)
```

具体权重放在配置文件中，不写死在模型类里。
多知识点题中，`primary_concept_id`（主要知识点）使用完整辅助损失权重，其他关联知识点使用较低权重。
这些权重都必须可配置，不得把一道题的对错当成所有关联知识点的真实掌握标签。

### 11.2 暂不开展完整实验

第一版不要求：

```text
大规模基线模型对比；
完整消融实验；
论文级参数搜索；
多模型集成；
不确定性网络；
专家教学效果实验。
```

### 11.3 最低可用验证

即使不以实验为主，也必须通过最低工程验证：

```text
数据编号、补位和多知识点解析正确；
训练损失能够下降；
验证集 AUC 高于随机水平 0.5；
模型输出位于 0 到 1；
输出不存在 NaN 或无穷值；
同一输入在 eval 模式下结果一致；
未来答案没有进入历史输入；
图只由训练数据构建；
导出模型可以在独立进程重新加载并推理。
```

这些属于模型可用性检查，不作为本阶段论文实验结论。

## 13. 在线接口

### 13.1 引擎接口

正式核心接口压缩为一次评估：

```python
class SAFKTEngine:
    def evaluate(
        self,
        history: list[GradedInteraction],
        target_question_id: str,
    ) -> SAFKTOutput:
        ...
```

一次模型前向同时得到预测、遗忘信号和注意力信号，避免分别调用诊断和解释导致重复推理或结果不一致。

现有 `KTStateEngine` 的 `update_from_event`、`diagnose` 和 `explain_prediction` 可以在迁移期作为兼容外壳，但内部必须复用同一次评估结果。

### 13.2 SAFKTOutput

```python
class SAFKTOutput(BaseModel):
    target_question_id: str
    target_concept_ids: list[str]
    prediction_probability: float
    concept_state_by_concept: dict[str, float]
    concept_evidence_count: dict[str, int]
    concept_evidence_sufficiency: dict[
        str, Literal["insufficient", "limited", "sufficient"]
    ]
    retention_by_concept: dict[str, float]
    forgetting_signal_by_concept: dict[str, float]
    key_history: list[dict]
    evidence_status: Literal["partial", "unavailable"]
    model_version: str
    mapping_version: str
    input_fingerprint: str
```

`input_fingerprint` 是输入历史、目标题和映射版本的稳定摘要，不包含学生原始答案全文。

## 14. TeachingState

### 14.1 定位

TeachingState 是本轮教学可以依赖的只读状态快照，不是聊天记录，也不是长期画像。

```text
SAFKTOutput 提供模型原始判断；
TeachingStateCompiler 合并判题事实、模型输出和证据门控结果；
教学模块只读取 TeachingState。
```

### 14.2 第一版字段

```python
class TeachingState(BaseModel):
    state_id: str
    student_id: str
    session_id: str
    target_question_id: str | None
    target_concept_ids: list[str]

    engine_name: Literal["safkt"]
    model_version: str
    mapping_version: str
    compiler_version: str

    prediction_probability: float | None
    mastery_by_concept: dict[str, float | None]
    mastery_evidence_count: dict[str, int]
    mastery_evidence_sufficiency: dict[
        str, Literal["insufficient", "limited", "sufficient"]
    ]
    mastery_source: Literal["model_estimate"]
    weak_concepts: list[dict]
    forgetting_signals: list[dict]
    key_history: list[dict]

    evidence_status: Literal["partial", "unavailable"]
    evidence_gaps: list[dict]
    input_fingerprint: str | None
    created_at: str
```

### 14.3 薄弱知识点规则

第一版使用可配置阈值：

```text
mastery is not None
mastery < 0.6
evidence_count >= 2
```

证据少于两次时可以标记“证据不足”，但不直接列为确定薄弱点。

### 14.4 错因字段

TeachingState 第一版不从 SAFKT 自动生成具体错因。

具体错因只能来自判题或步骤分析的直接证据；没有证据时为：

```text
mistake_type = unknown
```

不得根据注意力、低掌握度或常见错误模式自动写成学生事实。

---

## 15. 主链路

### 15.1 提交答案

```text
学生提交答案
→ 判题模块生成 grading_result
→ 保存作答事实
→ 检查是否允许进入正式 KT 历史
→ 将本次正式作答加入历史
→ 如果已有明确目标题，则执行 SAFKT-V2 预测
→ 编译并保存 TeachingState
→ 写入 Trace
→ 不自动触发 Agent 回复
→ 不自动推荐下一题
```

如果提交答案后尚无目标题：

```text
保存更新后的历史；
根据正式作答事实编译当前知识点状态；
prediction_probability 可以为空；
不得对刚加入历史的同一道题进行泄漏式预测。
```

### 15.2 请求下一题

```text
读取候选题
→ SAFKT-V2 对少量候选题批量评分
→ 为每个候选题生成答对概率
→ TeachingState / 推荐模块结合薄弱点和难度选择下一题
→ 保存 current_question
→ 保存推荐证据
```

### 15.3 Agent 对话

```text
Agent 判断问题是否需要知识追踪事实
→ 读取已经保存的 TeachingState
→ 不重新训练模型
→ 只有明确需要新目标题预测时才调用 SAFKT-V2
```

## 16. 错误处理

### 16.1 启动失败

以下情况视为 SAFKT 不可用：

```text
模型文件缺失；
配置文件缺失；
题目或知识点映射缺失；
图产物缺失；
manifest 哈希校验失败；
模型结构与 checkpoint 不匹配；
缺少 PyTorch 运行依赖。
```

行为：

```text
readiness（就绪检查）返回失败；
需要知识追踪的正式请求返回结构化错误；
不创建 mock；
不生成假的 TeachingState。
```

### 16.2 单次推理失败

```text
保留已经成功保存的判题和作答事实；
记录 failure_stage = safkt_inference；
本轮不生成新的成功 TeachingState；
返回可恢复的结构化错误；
不得把旧状态改时间后当成新状态。
```

### 16.3 映射失败

```text
未知题目编号 → 拒绝推理；
知识点与题目映射不一致 → 拒绝推理；
题目没有知识点映射 → 拒绝进入正式 SAFKT 历史；
```

映射失败不能通过“取第一个知识点”或“使用默认题号”绕过。

## 17. Trace 与隐私

Trace 至少记录：

```text
state_id
engine_name = safkt
model_version
mapping_version
compiler_version
target_question_id
target_concept_ids
prediction_probability
evidence_status
input_fingerprint
failure_stage
```

Trace 不记录：

```text
本机绝对 checkpoint 路径；
模型全部原始张量；
完整学生答案原文；
未脱敏的第三方配置；
内部 embedding（嵌入向量）。
```

## 19. 开发阶段

### 阶段一：数据能正确进入模型

```text

生成 valid_mask；

```

完成标准：一个批次的所有张量形状、编号、遮罩和时间特征通过自动检查。

### 阶段二：SAFKT-V2 能训练

```text
实现稀疏知识点超图；
实现稀疏题目转移图；

完成少量数据过拟合检查；
完成完整数据训练入口。
```

完成标准：损失下降，验证 AUC 高于 0.5，无标签泄漏。

### 阶段三：产物能独立推理

```text
导出模型和映射；
生成 manifest；
实现独立加载；
使用固定输入完成可重复推理。
```

完成标准：新进程只依赖导出产物即可得到相同结果。

### 阶段四：接入 MathTutor

```text
实现 SAFKTEngine；
实现 TeachingStateCompiler；
正式 factory 只创建 SAFKT；
接入提交答案、下一题和 Agent 读取链路；
写入 state_id 和模型版本 Trace。
```

完成标准：一条真实作答可以生成真实 TeachingState，错误时不会降级或伪造结果。

### 阶段五：后续增强

以下不属于第一版：

```text
DTransformer 式状态稳定约束；
关键历史删除消融；
概率校准；
UKT 式不确定性建模；
完整模型对比和论文实验。
```

只有第一版闭环稳定并出现明确需求后再增加。

## 22. 最终结论

```text
MathTutor 的正式知识追踪只使用 SAFKT-V2。
SAFKT-V2 使用 XES3G5M 重新训练，读取题目、多个知识点、对错和真实时间。
模型输出目标题概率、知识点状态估计、遗忘信号和关键历史。
知识点状态由受 QIKT 启发的输出头生成；TeachingStateCompiler 只做证据门控和结构编译，不自行计算新的掌握度。
教学、推荐和 Agent 只读 TeachingState，不读取模型原始张量。
模型缺失、映射错误或推理失败时明确报错，不降级到 DGEKT 或 mock。
当前阶段先完成真实可运行闭环，复杂实验和高级解释能力后置。
```
