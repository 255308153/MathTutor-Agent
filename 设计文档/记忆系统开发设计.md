# MathTutor Agent 记忆系统开发设计

> 状态：已废弃的 Graphiti 方案。正式实施依据见 `记忆模块开发设计（HMS落地版）.md` 和 `记忆模块数据与接口详细设计.md`。

## 1. 文档说明

本文档把 `重构思考/记忆模块.md` 中的目标设计进一步细化为可以实施的技术方案。

本文重点回答：

```text
记忆点从哪里产生。
哪些信息由代码提取，哪些信息交给 LLM（大语言模型）理解。
什么时候只能生成候选，什么时候可以写成正式长期记忆。
重复记忆如何查重、合并和保证不重复计数。
新旧记忆冲突时如何保留历史。
后台任务如何提炼、总结和归档记忆。
每轮回答如何按需读取少量相关记忆。
现有代码应当按什么顺序重构。
```

本文只设计学生记忆系统，不重新定义 KT（知识追踪）、RAG（检索增强生成）、TeachingState（教学状态）或推荐器的职责。

---

## 2. 一句话目标

```text
LLM 负责听懂学生说了什么，并整理成记忆候选；
代码负责判断候选是不是真的、证据够不够、是否重复，以及能不能写入长期画像。
```

核心边界：

```text
KT facts are authoritative.
KT 产生的学习事实具有最高权威性。

Memory can influence strategy, not mastery.
记忆可以影响教学策略，但不能修改掌握度。
```

### 2.1 模块负责

```text
保存当前 conversation 的短期对话。
接收学习事实和对话产生的 MemoryObservation。
提取 MemoryCandidate。
检查证据、质量、重复和冲突。
维护正式长期记忆及其状态。
把审核通过的长期记忆同步到 Graphiti。
按意图检索少量相关长期记忆。
在 Graphiti 故障时执行降级和补写。
```

### 2.2 模块不负责

```text
不负责保存正式作答和判题事实。
不负责判断答案正确性。
不负责决定作答能否进入 KT。
不负责计算 mastery、预测概率和遗忘风险。
不负责检索教材和题目解析。
不负责推荐下一题。
不负责生成最终教学回复。
```

### 2.3 与其他模块的简单联动

```text
学习事实模块 → 提供已保存的正式作答、判题和结果证据。
Agent / 对话模块 → 提供学生原话、AI 教学动作和明确反馈。
记忆模块 → 生成、审核和保存长期记忆。
Graphiti / Neo4j → 作为记忆模块内部的生产存储与检索 Adapter。
上下文模块 ← 只接收记忆模块返回的 MemoryContextResult。
```

其他模块不得直接写 Graphiti，也不得绕过 `LearningMemorySystem` 查询长期记忆。

## 3. 当前实现与目标差距

当前长期记忆实现主要位于：

```text
backend/app/memory/store.py
backend/app/memory/sqlite_store.py
backend/app/memory/mem0_provider.py
backend/app/graph/learning_loop.py
backend/app/context/learning_context.py
```

已有能力：

```text
StudentMemory（学生长期记忆模型）。
SQLite、进程内存、Fake Provider（模拟提供方）和 Mem0 存储适配。
长期记忆的搜索、查看、禁用、启用和删除。
Context（上下文）层对禁用和删除记忆的排除。
TeachingTrace（教学执行记录）中的记忆观察信息。
```

主要问题：

1. `MathTutorLearningLoop._load_context()` 基本每轮都会查询长期记忆和 RAG，没有先按意图判断是否需要。
2. `_update_memory()` 在一次答错后直接写 `repeated_mistake（反复错因）`。
3. `_update_memory()` 在一次答对后直接写 `effective_strategy（有效策略）`。
4. 当前只有 `session_id（学习会话编号）`，没有独立的 `conversation_id（聊天窗口编号）`。
5. `_persist_turn()` 主要保存 Trace 摘要，没有形成完整、稳定的交互原料记录。
6. 当前没有记忆候选、证据账本、质量门槛、冲突判断和持久化后台任务。

因此，现有 `StudentMemoryStore（学生记忆存储接口）`可以保留，但主循环不能继续直接决定长期画像内容。

## 4. 总体分层

### 4.1 Conversation Memory（对话短期记忆）

保存当前聊天窗口最近 3～5 轮完整问答。

```text
作用范围：conversation_id
主要用途：理解“这里”“刚才那一步”“继续讲”等指代
生命周期：当前聊天窗口或短期保留
是否跨聊天窗口：否
```

### 4.2 Learning Facts（学习事实）

Learning Facts 是记忆模块读取的外部输入，不是记忆模块自己拥有的数据层。

```text
题目、学生正式提交、标准答案、判题结果、是否查看答案、当前题、学习进度、KT 结果。
```

这些内容属于学习事实模块的事实账本，不属于学生画像。记忆模块只能按引用读取，不能修改或复制出另一套权威事实。

### 4.3 Memory Observation（记忆原料）

保存可能用于提炼长期记忆的原始证据。

```text
student_evidence：学生原话、正式作答、换题反馈。
assistant_action：AI 使用过的提示、讲解、推荐和教学策略。
outcome_evidence：后续正式答题结果或学生明确反馈。
```

### 4.4 Memory Candidate（记忆候选）

候选表示“可能值得记住”，不表示已经成为学生长期画像。

候选必须经过：

```text
质量检查 -> 证据检查 -> 结构化归一 -> 查重 -> 冲突判断 -> 写入门槛判断
```

### 4.5 Long-term Memory（长期记忆）

保存跨聊天窗口仍然有教学价值的稳定画像。

```text
preference：学习偏好
repeated_mistake：反复错因
effective_strategy：有效教学策略
reflection：学习目标、节奏和自我反思
```

### 4.6 Graphiti 的正式定位

Graphiti 从第一阶段开始接入，并作为生产环境默认的长期关系记忆查询和关系存储实现。

```text
本地事实账本：保存审核后的正式记忆、证据、状态和待同步任务。
Graphiti：保存正式记忆的时间关系图，并承担生产环境默认检索。
本地投影：测试使用，同时作为 Graphiti 故障时的降级读取来源。
```

Graphiti 不是判题、KT 或正式学习事实的权威来源。Graphiti 故障不能影响这些主链路。

第一阶段技术选型：

```text
Graphiti 图数据库：Neo4j。
关系提取 LLM：云端 DeepSeek V4 Pro。
Embedding：待确定，接入前完成模型和维度兼容性验证。
```

## 5. 核心身份字段

```text
student_id：学生编号，长期画像按它共享。
session_id：一段连续学习过程的编号。
conversation_id：一个 Agent 聊天窗口的编号。
turn_id：一次学生输入和 AI 回复的编号。
event_id：一次正式学习事件的编号。
trace_id：一次系统执行和证据审计的编号。
```

兼容旧请求时：

```text
conversation_id = "legacy:" + session_id
```

新聊天窗口只创建新的 `conversation_id`，不会清空学生的 KT、当前题、学习事实和长期画像。

## 6. 记忆系统的外部接口

主循环只依赖一个深模块：

```python
class LearningMemorySystem:
    def context_for(self, request: MemoryContextRequest) -> MemoryContextResult:
        """按意图读取当前对话和相关长期画像。"""

    def observe(self, observation: MemoryObservation) -> ObservationReceipt:
        """保存记忆原料并创建后台提炼任务，不直接生成正式长期记忆。"""
```

模块内部可以继续拆分：

```text
ConversationMemoryStore（对话短期记忆存储）
MemoryObservationStore（记忆原料存储）
MemoryCandidateExtractor（记忆候选提取器）
MemoryQualityGate（记忆质量检查器）
MemoryDeduplicator（记忆查重器）
MemoryConflictResolver（记忆冲突处理器）
LearningMemoryRefinery（学习记忆提炼器）
StudentMemoryStore（长期记忆存储）
MemoryRetriever（长期记忆检索器）
```

这些内部模块不应全部暴露给 `MathTutorLearningLoop`。

## 7. 记忆点如何提取

采用“代码直接提取 + LLM 结构化提取 + 系统最终验证”的混合方案。

### 7.1 代码直接提取

以下信息已经是结构化事实，不需要调用 LLM：

```text
正式提交了哪道题。
答案是否正确。
确定性错因编码。
是否查看答案或跳过。
本轮使用了哪种教学策略。
后续作答是否改善。
学生选择了哪种难度或题型。
```

示例：

```json
{
  "event_id": "event_answer_018",
  "question_id": "q_018",
  "concept_id": "c_fraction_addition",
  "is_correct": false,
  "mistake_code": "missing_common_denominator"
}
```

代码可以直接生成候选证据：

```text
memory_type = repeated_mistake
memory_key = mistake:c_fraction_addition:missing_common_denominator
```

但第一次出现时只保存候选，不直接写成“反复错因”。

### 7.2 LLM 结构化提取

以下自然语言信息适合交给 LLM 理解：

```text
学生明确表达的讲解偏好。
学生对难度、节奏和题型的感受。
学生表达的学习目标或自我反思。
学生对某种讲法的正面或负面反馈。
学生在聊天草稿中表现出的可能错误模式。
```

示例输入：

```text
学生：你别一下子把答案告诉我，先提示我第一步。
```

LLM 必须输出固定结构，而不是直接写一段自由文本：

```json
{
  "has_candidate": true,
  "candidates": [
    {
      "memory_type": "preference",
      "dimension": "hint_depth",
      "value": "first_step_only",
      "scope": "global",
      "summary": "学生偏好先获得第一步提示，而不是直接查看完整答案。",
      "evidence_quote": "先提示我第一步",
      "source_role": "student",
      "reason": "学生明确表达了提示深度偏好"
    }
  ]
}
```

LLM 的输出仍然只是候选。

### 7.3 LLM 调用前的过滤

以下情况不调用 LLM：

```text
普通闲聊。
纯按钮操作。
只有结构化正式答案提交。
没有教学相关内容。
内容过短且没有明确偏好或反馈信号。
同一 turn_id 已经处理过。
```

以下情况可以调用：

```text
学生要求改变讲解方式。
学生表示题目太难或太简单。
学生进行学习复盘。
学生表达长期目标或稳定困难。
学生明确评价某种讲法是否有帮助。
```

### 7.4 Evidence Package（证据包）

每次只给 LLM 当前相关内容，不把全部历史塞进去：

```json
{
  "student_message": "你别直接说答案，提示第一步就行",
  "assistant_response": "好，我们先找两个分母的最小公倍数。",
  "intent": "stuck_on_current_problem",
  "question_id": "q_018",
  "concept_id": "c_fraction_addition",
  "used_strategy": "first_step_hint",
  "formal_result": null,
  "previous_related_candidates": []
}
```

AI 回复只能证明“系统说过或做过什么”，不能证明学生掌握或没有掌握。

### 7.5 LLM 输出后的系统验证

代码必须再次检查：

```text
evidence_quote 是否真实出现在原文中。
memory_type 是否属于允许范围。
concept_id 和 question_id 是否真实存在。
是否错误生成 mastery、prediction_probability 等 KT 字段。
是否把 AI 的话当成学生事实。
是否把 RAG 中的常见错因当成学生本次真实错因。
是否包含敏感信息。
是否缺少 evidence_id。
```

任意一项不合格，候选进入 `rejected（已拒绝）`，并记录原因。

## 8. 四类记忆的提取和写入门槛

### 8.1 preference（学习偏好）

主要证据：学生原话、连续选择和明确反馈。

示例：

```text
“先给我提示，不要直接说答案。”
“我想看一步一步的过程。”
“这类题先从简单的开始。”
```

归一字段：

```text
hint_depth = first_step_only
explanation_style = step_by_step
difficulty_preference = easy_first
```

正式写入条件：

```text
学生明确表达一次；
或者多个独立回合出现一致选择。
```

### 8.2 repeated_mistake（反复错因）

主要证据：正式作答、明确步骤和确定性错因规则。

LLM 可以提出 `possible_mistake（可能错因）`，但不能单独把它升级为正式错因。

正式写入条件：

```text
至少两次独立正式作答；
属于同一知识点和同一错因编码；
错因能够由正式答案、步骤或确定性规则确认；
重复提交同一道题同一答案只计算一次。
```

### 8.3 effective_strategy（有效策略）

必须同时具备：

```text
strategy_exposure：AI 确实使用过该教学策略。
outcome_evidence：之后出现明确正面反馈或正式作答改善。
```

LLM 可以判断学生反馈是正面、负面还是不明确，但不能只根据 AI 回复判断策略有效。

### 8.4 reflection（学习反思）

主要证据：学生明确表达的目标、习惯和自我认知。

示例：

```text
“我一看到应用题就容易读得太快。”
“我最近想先把分数题练熟。”
```

反思摘要必须保留学生原话引用，不能改写成绝对结论。

## 11. 查重设计

### 11.1 memory_key（记忆识别键）

不同类型使用不同结构：

```text
mistake:{concept_id}:{mistake_code}
preference:{dimension}:{value}:{concept_scope}
strategy:{concept_id}:{strategy_code}
reflection:{topic}:{concept_scope}
```

### 11.2 查重顺序

```text
1. 相同 evidence_id：重复任务，直接忽略。
2. 相同 memory_key：合并到已有记忆。
3. 关键字段相同且文字高度相似：自动合并。
4. 文字相似但关键字段冲突：进入 conflict。
5. 没有匹配：创建新记忆或继续保留候选。
```

### 11.3 文本相似度

第一期优先使用：

```text
结构化字段匹配
归一化关键词
标签交集
简单文本相似度
```

后续可以增加 `Embedding（文本向量）`发现可能重复项，但向量结果只负责召回候选，不能单独决定合并。

### 11.4 合并操作

```text
合并证据引用。
evidence_count 增加。
更新 last_observed_at。
重新计算 confidence。
必要时更新 summary。
version + 1。
写 memory_update_logs。
```

同一个 `evidence_id`重复执行不会重复增加证据，保证 `Idempotency（幂等性）`。

## 12. 冲突和时间变化

记忆状态：

```text
active：当前有效
superseded：已被新记忆替代
stale：长期没有新证据，可能过时
archived：只保留审计，不参与普通检索
deleted：已删除
```

示例：

```text
旧记忆：学生偏好简单题。
新证据：学生近期多次认为题目太简单。
```

处理方式：

```text
保留旧记忆和旧证据。
旧记忆 valid_to 记录失效时间。
旧记忆状态改为 superseded。
新建或更新“当前更偏好中等难度”。
新记忆记录 replaced_memory_id。
```

一次反向证据不能直接删除旧记忆。只有连续、独立的反向证据才能改变当前状态。

## 13. 可信度计算

LLM 可以提供辅助判断，但最终可信度必须由代码根据证据计算。

### 13.1 repeated_mistake

```text
1 次正式错误：只保留候选。
2 次独立正式错误：写入，confidence = 0.70。
3 次独立正式错误：confidence = 0.82。
4 次及以上：最高 0.95。
```

### 13.2 preference

```text
学生明确表达：0.75。
第二次独立支持：0.85。
连续一致选择：逐步增加，最高 0.95。
```

### 13.3 effective_strategy

```text
第一次完整的“策略使用 + 正向结果”：0.65。
第二次独立验证：0.80。
后续稳定验证：最高 0.95。
```

### 13.4 reflection

```text
学生明确自述：0.70。
后续一致表达或行为支持：逐步提高。
```

可信度表示证据充分程度。`freshness（新鲜度）`单独参与检索排序，不因时间过去直接修改历史可信度。

## 14. 长期记忆摘要生成

优先使用结构化模板：

```text
学生在「{知识点}」中多次出现「{错因名称}」。
学生偏好「{讲解方式}」。
「{教学策略}」在后续学习结果中得到正向验证。
学生近期表达的学习目标是「{目标}」。
```

LLM 只允许做受限制的语言润色：

```text
不能增加新事实。
不能删除证据限制。
不能使用“总是、从不、完全不会”等绝对词。
不能把候选描述成已经确认的事实。
不能写 mastery、prediction_probability 等 KT 字段。
```

错误表达：

```text
学生不会异分母分数加法。
```

正确表达：

```text
学生近期在异分母分数加法中多次遗漏寻找公分母这一步。
```

## 15. 后台提炼与定时总结

### 15.1 每轮交互结束

主请求只做：

```text
保存 conversation_turn。
保存 memory_observation。
创建 memory_refinery_job。
返回学生回复。
```

不在主请求中完成长期记忆总结。

### 15.2 每分钟处理待办任务

`MemoryRefineryWorker（记忆提炼后台程序）`轮询 `pending（等待处理）`任务：

```text
领取任务 -> 提取候选 -> 质量检查 -> 查重 -> 合并或等待 -> 写审计日志
```

任务状态：

```text
pending：等待处理
running：正在处理
completed：处理完成
failed：处理失败
```

通过 `lease_until（任务租约到期时间）`处理工作进程异常退出后的重新领取。

### 15.3 每日增量总结

每天只处理当天产生新证据的学生：

```text
整理最近 7 天候选。
合并同类候选。
检查新旧记忆冲突。
更新摘要和可信度。
把证据不足的候选继续保留为 pending。
```

### 15.4 每周维护

```text
合并残留重复项。
归档已被替代的记忆。
标记长期无新证据的 stale 记忆。
检查单个学生长期记忆数量。
检查没有证据关联的异常记忆。
```

不建议只使用 FastAPI `BackgroundTasks（进程内后台任务）`，因为服务重启后任务可能丢失。第一期使用 SQLite 持久任务表即可，不必立即引入消息队列。

## 16. 记忆读取设计

### 16.1 按意图决定是否读取

| 场景 | 长期记忆读取策略 |
|------|------------------|
| 提交答案 | 不读取 |
| 普通闲聊 | 不读取 |
| 当前题提示 | 读取相关偏好、反复错因和有效策略 |
| 错因解释 | 读取相关错因和讲法偏好 |
| 下一步建议 | 读取偏好和有效策略 |
| 推荐原因解释 | 可选读取 |
| 学习总结 | 读取四类长期记忆 |
| 普通数学概念 | 通常优先 RAG，不读取学生记忆 |

### 16.2 硬过滤

```text
student_id 必须一致。
status 必须允许参与检索。
disabled 和 deleted 记忆必须排除。
confidence 必须达到当前意图要求。
知识点和记忆类型必须符合读取策略。
```

### 16.3 排序因素

```text
当前问题相关程度。
知识点或题目匹配程度。
可信度。
新鲜度。
记忆类型优先级。
近期使用效果。
```

每轮最多返回 3～5 条，同一类型最多 2 条，避免某一种记忆占满上下文。

系统因策略决定“不读取”时，不记录“无可用记忆”缺口。只有实际查询后为空或 Provider（外部提供方）失败时，才记录 evidence gap（证据缺口）。

## 17. Provider（外部提供方）职责

生产默认和容错 Adapter：

```text
GraphitiLongTermContextStore（生产默认）。
SqliteStudentMemoryStore（正式记忆账本和降级投影）。
InMemoryStudentMemoryStore（进程内存实现）
FakeStudentMemoryProvider（模拟实现）
Mem0StudentMemoryStore（Mem0 实现）
```

MathTutor 自己负责：

```text
记忆写入门槛。
证据是否合法。
结构化查重。
冲突处理。
可信度。
记忆状态变化。
KT 权威保护。
```

Graphiti、Mem0 或其他外部 Provider 只负责关系存储和检索，不能成为学生画像事实是否成立的最终裁判。

Provider 失败时：

```text
学生主学习流程继续。
不伪造记忆。
记录 provider_failure。
Graphiti 查询失败时，熔断并读取本地已审核记忆投影。
Graphiti 写入失败时，正式记忆保留在本地事实账本并进入待同步队列。
后台任务按 memory_id 幂等重试。
Graphiti 恢复后完成补写，再退出降级状态。
```

### 17.1 删除与 Graphiti 同步

删除单条长期记忆时：

```text
本地正式记忆标记 deleted 并立即退出检索。
删除或失效对应 Graphiti 关系。
删除尚未执行的写入同步任务。
Graphiti 不可用时创建幂等删除任务，恢复后继续执行。
```

删除整个学生时，必须清除该学生的正式记忆、证据链接、候选、Graphiti 关系和待同步任务。只允许保留不含正文和可识别学生 ID 的聚合指标。

## 18. 记忆使用效果反馈

每次长期记忆进入上下文时，记录：

```text
memory_id
为什么被选中
影响了哪项教学动作
本轮最终采用的讲解策略
后续学生反馈
后续正式作答结果
```

使用结果：

```text
helpful：有帮助
neutral：没有明显影响
harmful：产生误导
unknown：暂无结果
```

记忆被多次检索不代表它有效。只有后续结果证据才能提高“有效策略”类记忆的可信度。

多次 `harmful（有害）`应降低检索优先级或停用记忆。

## 20. 测试与验收

必须覆盖：

```text
一次答错不会形成反复错因。
两次独立、确定的相同错因可以形成长期记忆。
重复提交同一事件不会增加证据数量。
AI 自己说“学生不会”不能形成学生事实。
RAG 常见错因不能直接成为学生本次错因。
使用策略但没有后续结果时不能标记为有效。
学生明确偏好可以生成带原话引用的候选。
相同 memory_key 会合并而不是新增。
关键字段冲突时不会仅凭文本相似自动合并。
新偏好替代旧偏好时保留历史证据。
新聊天窗口不继承旧窗口完整聊天，但可以读取长期画像。
提交答案和闲聊不查询长期记忆。
disabled、deleted、stale 记忆按策略正确排除。
Provider 失败不阻断主学习流程。
Graphiti 查询失败时能够读取本地已审核记忆投影，并明确标记 degraded。
Graphiti 写入失败时正式记忆仍在事实账本，且只生成一条待同步任务。
Graphiti 恢复后按 memory_id 幂等补写，不重复生成关系。
后台任务失败重试不会重复写入。
Memory 中伪造的 mastery 不能覆盖 KT。
```

建议指标：

```text
写入准确率。
错误记忆率。
重复记忆率。
证据可追溯率。
相关记忆召回率。
无关记忆召回率。
冲突处理正确率。
KT 边界违规数量。
后台任务成功率和重试成功率。
```

## 21. 参考实现与吸收边界

### Claude Code

吸收：短索引、详细内容按需读取、不是每轮都写记忆。

不照搬：使用本地 Markdown 文件作为多学生系统的主存储。

### Codex

吸收：等待任务空闲后后台提取、单次提取和全局合并分开、保留支持证据。

不假设：未公开的具体查重公式和内部提示词。

### ProbeFlow

吸收：候选、质量门槛、事实指纹、相同来源去重、相似事实合并、关键字段冲突和证据账本。

需要改造：把测试领域字段替换为学生、知识点、错因、教学策略和学习结果。

参考：<https://github.com/255308153/ProbeFlow>

### Graphiti

吸收：事实有效时间、旧事实保留、冲突和替代关系、来源追踪。

接入方式：Graphiti Adapter 从第一阶段开始接入，并作为生产默认实现；本地 Adapter 保留给测试、离线开发和故障降级。Graphiti 只接收经过记忆提炼和证据审核的长期关系，不能成为 KT、判题或正式学习事实的唯一数据源。

参考：<https://github.com/getzep/graphiti>

### LangMem

吸收：Hot Path（主流程）与 Background Manager（后台记忆管理器）分开。

参考：<https://github.com/langchain-ai/langmem>

### Mem0

吸收：Provider 适配、用户级存储和语义检索。

不照搬：让外部 Provider 决定学生画像是否成立。

参考：<https://github.com/mem0ai/mem0>

```text
LongMemEval：知识更新、时间推理、跨会话检索和无证据拒答。
LoCoMo：超长多会话对话和事件总结。
```

## 22. 最终结论

MathTutor 的长期记忆不是“让 LLM 看完聊天后写一句总结”。

正确实现是：

```text
结构化学习事件由代码直接提取；
自然语言由 LLM 整理成带原话引用的结构化候选；
正式写入由证据规则、查重规则和冲突规则决定；
后台任务负责延迟提炼、每日总结和定期归档；
每轮只按意图读取少量相关记忆；
任何记忆都不能覆盖 KT 产生的学习事实。
```
