# TeachingState 模块设计（简化版）

这份文档用于说明 **知识追踪模型** 和 **TeachingState 模块** 在系统中的作用。

当前阶段不追求复杂的模型解释体系，先保留最核心、最适合教学 Agent 使用的设计。

---

## 1. 模块一句话定义

```text
TeachingState 模块负责把知识追踪模型输出的学习状态，
整理成本轮教学决策可以直接使用的结构化状态。
```

更简单地说：

```text
知识追踪模型负责判断学生会不会；
TeachingState 模块负责把事实和证据整理成可读取的状态。
```

它是 **知识追踪模型** 和 **教学 Agent** 之间的中间层。

---

## 2. 这个模块解决什么问题

学生做题之后，系统不能只知道“答对了”或“答错了”，还需要进一步判断：

```text
学生主要不会哪个知识点？
这次错误属于什么类型？
为什么系统认为学生在这里有问题？
这个知识点是否需要复习？
下一步应该怎么讲、怎么提示、推荐什么练习？
```

TeachingState 就是把这些判断整理成统一状态，给后面的回复、讲解生成和练习推荐使用。

---

## 3. 模型侧保留的四个优化点

为了让 TeachingState 更有教学价值，知识追踪模型不只输出答对概率，还需要做一些面向教学的优化。

第一版先保留四个优化点。

### 3.1 知识点掌握度输出

模型不只预测学生某道题能不能答对，还要输出学生对相关知识点的掌握情况。

例如：

```text
知识点：一元一次方程
掌握度：0.42
判断：掌握不稳定，需要继续练习
```

作用：

```text
让系统知道学生弱在哪个知识点，而不是只知道某道题错了。
```

### 3.2 错误类型判断

只有有直接证据时，规则或后处理层才判断学生这次错误属于哪一类。
无法确定时保留未知，不主动询问学生，也不把常见错因当成学生事实。

常见错误类型：

```text
概念理解错误
解题步骤错误
计算错误
公式或规则记忆错误
审题错误
知识迁移错误
```

作用：

```text
不同错误类型对应不同教学方式。
概念错就重新讲概念；
步骤错就拆步骤；
计算错就引导检查；
记忆错就安排快速复习；
迁移错就做变式题。
```

### 3.3 注意力权重转关键历史记录

如果模型内部有注意力机制，不直接把一堆权重交给教学模块。

TeachingState 只需要保留模型认为最重要的历史记录。

例如：

```text
最近 3 次相似题中，有 2 次在移项步骤出错。
上一次同知识点题目答错，错误点也是符号变号。
```

作用：

```text
让系统可以解释“为什么这么判断”，而不是只给一个分数。
```

### 3.4 遗忘风险显式输出

模型需要明确输出学生对某些知识点是否存在遗忘风险。

可以简化成：

```text
低风险
中风险
高风险
```

作用：

```text
帮助系统决定是否安排复习题。
高遗忘风险 -> 优先复习；
中等遗忘风险 -> 后续穿插练习；
低遗忘风险 -> 暂不复习。
```

---

## 4. TeachingState 接收什么

TeachingState 主要接收两类信息。

### 4.1 当前学习事件

```text
学生编号
当前会话
当前题目
学生答案
是否答对
当前知识点
最近学习记录
```

### 4.2 知识追踪模型输出

```text
知识点掌握度
薄弱知识点
关键历史记录
遗忘风险
答对概率
```

---

## 5. TeachingState 输出什么

TeachingState 最终输出的是事实、证据和可供参考的建议，不直接决定最终回复。

第一版可以保留这些字段：

```text
student_id
学生编号

session_id
当前学习会话编号

current_question
当前题目信息

target_concept
当前知识点

mastery_level
知识点掌握程度

weak_concepts
薄弱知识点

mistake_type
有直接证据时记录错误类型；否则为 unknown

key_history
关键历史记录

forgetting_risk
遗忘风险

teaching_suggestion
教学建议

recommendation_direction
推荐练习方向
```

这些字段不需要一开始设计得很复杂，只要能支撑教学决策即可。

## 6. 简单示例

学生做一道一元一次方程题答错。

模型与确定性证据整理后：

```text
知识点掌握度：一元一次方程 0.42
薄弱知识点：移项
错误类型：解题步骤错误（仅在作答步骤或明确规则能够证明时）
关键历史记录：最近 3 次移项题有 2 次出错
遗忘风险：中等
答对概率：0.38
```

TeachingState 整理后：

```text
当前教学重点：移项
本次主要问题：步骤错误
提示深度：需要拆步骤讲解
下一步教学建议：先讲一道例题，再让学生补全下一步
推荐练习方向：低中难度的移项练习
复习安排：后续穿插一题一元一次方程复习题
```

这样，后面的教学 Agent 就不用直接理解模型内部细节，只需要读取 TeachingState。

## 7. 在系统中的位置

整体链路可以理解为：

```text
学生学习事件
  -> 知识追踪模型
  -> TeachingState 模块
  -> 教学规划模块
  -> 生成讲解 / 推荐练习 / 安排复习
```

更口语一点：

```text
学生做题记录
  -> 判断学生状态
  -> 整理教学状态
  -> 决定怎么教
```

---

## 8. 模块边界

TeachingState 负责：

```text
整理模型输出
形成教学状态
给回复流程和练习推荐提供依据
给推荐练习提供方向
给教学解释提供关键证据
```

TeachingState 不负责：

```text
不直接生成最终回复
不负责检索知识库
不负责保存长期记忆
不负责判题
不负责训练模型
```

它只做一件事：

```text
把“学生会不会、为什么不会、是否需要复习”
整理成“下一步怎么讲、提示多深、推荐什么练习”。
```

---

## 9. 和其他模块的关系

### 9.1 和知识追踪模型的关系

```text
知识追踪模型提供原始判断；
TeachingState 把原始判断整理成教学可用状态。
```

### 9.2 和教学规划模块的关系

```text
回复流程读取 TeachingState，
根据学生主动提出的问题决定回复内容；练习推荐只在需要下一题时读取它。
```

### 9.3 和 RAG 知识库的关系

```text
TeachingState 判断学生哪里弱；
RAG 负责提供对应知识点的讲解材料和引用内容。
```

### 9.4 和记忆模块的关系

```text
TeachingState 表示学生当前学习状态；
记忆模块记录学生长期偏好、学习习惯和历史画像。
```

---

## 10. 本阶段结论

第一版 TeachingState 不需要设计得过重。

只要能稳定表达下面五类信息，就可以支撑教学 Agent 的基础闭环：

```text
学生当前弱在哪
这次错在哪里
为什么系统这样判断
是否需要复习
下一步应该怎么教
```

对应模型侧先保留四个优化点：

```text
知识点掌握度输出
错误类型判断
注意力权重转关键历史记录
遗忘风险显式输出
```

一句话总结：

```text
TeachingState 是知识追踪模型和教学 Agent 之间的教学状态中间层。
它不负责直接讲课，而是负责把模型判断整理成可执行的教学依据。
```
