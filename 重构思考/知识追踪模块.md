# 知识追踪模块（终极版大致设计）

> 本文保留知识追踪模块的总体构想。已经定稿的运行时、数据、失败处理和第一版开发细节，
> 以 `设计文档/知识追踪模块开发设计.md` 为准；两者冲突时以后者为准。

这份文档写 **知识追踪 + 教学状态** 在本项目里怎么接、怎么用。  
不做模型实验、不设基线对比——那部分已有；这里只管 **接入 Agent 与教学闭环**。


## 1. 一句话目标

```text
把已有的 SAFKT（DGEKT + 自注意力 + 遗忘等）接到 Agent 里；
每轮产出一份带版本、依据、置信度的 TeachingState；
教学只读这份状态做提示、纠错、练习；
讲错了能查回模型依据，换模型/映射也能扫到受影响的教学资产。
```

```text
会不会  →  SAFKT（可降级 DGEKT / mock）
怎么教  →  只读 TeachingState，不能改会不会
```

## 2. 模型叫什么（定名，写死）

| 名字 | 含义 |
|------|------|
| **SAFKT** | **本项目主知识追踪模型家族**（唯一对外模型名） |
| **SAFKT-V2** | 面向 XES3G5M 和教学决策改进后的正式模型版本 |
| **DGEKT** | 原版底座结构；SAFKT 在其上加了自注意力、遗忘等 |
| 源码 `class DKT` | **仅实现类名**，禁止当作模型名写进文档/Trace/engine_name |

```text
对外模型家族名：SAFKT。
第一版正式模型版本：SAFKT-V2。
TeachingState 和 Trace 的正式 `engine_name` 固定记录为 `safkt`，另行记录 `model_version`。

结构关系（叙述用）：
  SAFKT-V2 = SAFKT 主干 + 真实时间遗忘 + 知识点状态输出头 + 结构化证据

源码事实（实现用）：
  Model.py 里 class 仍叫 DKT → 适配层 import 它，但包装成 SAFKT 引擎
```

本项目职责：

```text
以现有 SAFKT 实现为主干起点，完成面向 XES3G5M 的 SAFKT-V2 改造与重新训练。
正式链路为：加载 SAFKT-V2 产物 → 在线推理 → 编译 TeachingState → 给教学用。
现有 ASSIST2017 checkpoint 不能进入 XES3G5M 正式链路。
```

## 4. 解决什么 / 不解决什么

### 要解决（本项目工程）

```text
1. 使用 XES3G5M 改造并重新训练 SAFKT-V2
2. 同时输出目标题概率、知识点状态、遗忘信号和关键历史
3. SAFKT-V2 推理结果进 Agent，而不是 LLM 瞎猜水平
4. 原始模型输出 → 教学能用的 TeachingState
5. 提示 / 错因 / 练习对齐同一份状态
6. 异常讲解能回到模型输入与证据
7. 换 checkpoint / 映射时能标出版本、扫描影响面
```

### 不解决（别写进本模块设计）

```text
大规模 DKT/SAKT/AKT 基线对比
论文级消融实验和大规模参数搜索
判题、RAG 检索、学生记忆画像
聊天话术润色
```

## 5. 核心原则

```text
1. 会不会只由 KT 引擎写（终局主引擎 = SAFKT）
2. 模型原始输出不直接进 LLM；先编译 TeachingState
3. 归因/注意力权重只解释预测，不覆盖预测
4. 遗忘风险终局来自 SAFKT 遗忘机制，不由回复流程猜测
5. 自注意力权重尽量进 attribution，供「为什么这么判」
6. 降级可以教，不能装成「证据充分」
7. 双向对账：教学→模型依据；变更→受影响资产
```

## 6. 模块结构（工程）

```text
┌──────────────────────────────────────┐
│  KT 引擎层                            │
│  mock | dgekt(原版) | safkt(主模型)    │
│  update / diagnose / explain         │
└──────────────────┬───────────────────┘
                   │
                   ▼
┌──────────────────────────────────────┐
│  TeachingState 编译层                 │
│  映射 · 聚合 · 版本 · 置信度 · 提示建议 │
└──────────────────┬───────────────────┘
                   │ 只读
                   ▼
     Runtime 工具 / 回复流程 / 推荐 / Trace
```

建议路径：

```text
backend/app/kt/
  engine.py              # 接口（已有）
  factory.py             # 增加 safkt
  mock_engine.py         # 已有
  dgekt_engine.py        # 已有，原版
  safkt_engine.py        # 新增：加载 SAFKT 产物并推理
  teaching_state.py      # 新增：编译 TeachingState
  offline_evidence.py    # 已有，可复用/扩展归因
```

接口（沿用现缝，不推倒）：

```text
KTStateEngine
  update_from_event(progress, event) → progress
  diagnose(progress, target_question_id?) → 诊断中间结果
  explain_prediction(progress, target_question_id) → 归因原料
    （含自注意力关键历史、遗忘相关信号等）

TeachingStateCompiler
  compile(...) → TeachingState
```

配置示意：

```text
kt_engine = safkt                  # 正式运行唯一引擎；mock 只用于测试替身
# safkt checkpoint / 映射 / 校准文件路径等
```

## 7. SAFKT 接到系统里要出什么

引擎侧至少稳定提供：

```text
prediction_probability     # 当前题答对概率
mastery / weak_concepts    # 知识点层面；由 SAFKT-V2 知识点状态输出头生成
forgetting_risks           # 遗忘机制输出
attention 相关             # 自注意力：关键历史步、权重摘要
attribution 原料           # paths / key_history / gaps
model_version              # checkpoint / 产物版本
```

TeachingState 再编成教学契约（见下节）。  
**模型内部结构细节不写进 Agent 热路径**；只通过引擎适配器吃约定输出。

## 8. TeachingState：教学唯一权威读物

### 是什么

```text
本轮教学可以依赖的结构化学习状态。
不是 chat log，不是 RAG，不是 Memory。
```

事实分工：

```text
学习记录保存学生真实做过什么。
判题模块负责 is_correct 和标准答案对照。
KT 引擎负责 prediction、知识点状态估计和其他模型信号。
TeachingStateCompiler 只负责证据门控和结构编译，不使用透明规则另行计算 mastery。
TeachingState 把模型结果和可验证的确定性派生结果整理成版本化快照，不脱离证据创造事实。
```

### 大致字段

```text
identity
  student_id, session_id / turn_id
  target_question_id, target_concept_ids[]
  state_id

model
  engine_name                 # 正式运行固定为 safkt；测试替身不进入正式 TeachingState
  model_version
  data_schema_version         # ID / 映射版本
  compiler_version

prediction
  prediction_probability      # 教学用（若有校准则用校准后）
  mastery_by_concept{}
  weak_concepts[]
  forgetting_risks[]          # 来自遗忘机制
  difficulty_match            # 若有
  attention_signals{}         # 自注意力摘要

confidence
  overall
  calibration?                # 若已有校准产物则挂上；没有就标明 missing

attribution
  evidence_status             # complete | partial | unavailable
  top_paths[]
  key_history[]               # 可对齐自注意力高权重历史
  evidence_gaps[]

mistake
  mistake_type                # 有直接证据才填写，否则 unknown
  evidence_refs[]

provenance
  input_fingerprint           # 历史序列 / 目标 / 映射摘要
  created_at
```

### 读写权限

```text
写：判题模块写判题事实；KT 引擎写掌握度等模型事实；Compiler 只生成 TeachingState 快照
读：Runtime 只读工具、回复流程、Recommender、Context、Trace
禁写：RAG、Memory、LLM、前端
```

### 和现有代码对象

| 现有 | 终局 |
|------|------|
| `KTDiagnosis` | 编译前中间结果，或内嵌进 TeachingState |
| `AttributionEvidence` | → `attribution` |
| `authoritative_kt_facts` | 由 TeachingState **投影**，不要两套权威 |
| `KTLearningProgress` | 长期进度；TeachingState 是本轮快照 |
| `MathTutorState` | 整轮编排；KT 段挂 TeachingState |

原则：

```text
对外只认 TeachingState
对内引擎可保留 diagnosis / attribution 细节
```

## 9. 主链路（事件进来后）

```text
LearningEvent
  → 判分（如需要）
  → 保存学习事实
  → update_from_event
  → SAFKT 推理 + explain
  → 编译 TeachingState
  → Context 组装（TeachingState 事实不可裁）
  → 只读工具挂载
  → 推荐 / 回复流程读 TeachingState
  → 学生反馈
  → Trace 记 state_id + model_version + 关键证据
```

| 教学能力 | 主要读 |
|----------|--------|
| 错因诊断 | weak_concepts、attribution、判分结果 |
| 分层提示 | TeachingState 事实 + TeachingPlanner 规则 |
| 练习规划 | weak、forgetting signals + PracticePathPlanner 规则 |
| 下一步建议 | 同上 + mastery |

和 RAG / Memory：

```text
TeachingState：会不会、弱在哪、证据是否充分
RAG：标准怎么讲、引用哪段
Memory：这个学生习惯怎么讲

冲突时：判题事实认判题结果；会不会认 TeachingState；资料内容认 RAG；讲法偏好认 Memory。
```

## 10. 双向对账（简版）

### 正向：教学 → 模型

```text
trace_id
  → state_id / TeachingState
  → model_version
  → input_fingerprint
  → attribution（含注意力关键历史）
  → 本轮 hint / 推荐 / plan
```

### 反向：变更 → 资产

```text
换 safkt checkpoint / 映射 / compiler 规则
  → 标记旧 TeachingState 版本过期
  → 失效相关缓存策略
  → Trace 上能看出「不能跟旧版硬比」
```

最小做法：每份 TeachingState 自带版本号；Trace 存引用 + 摘要。

## 11. 失败处理

| 情况 | 行为 |
|------|------|
| 无 SAFKT 产物 | SAFKT 不可用；KT 相关请求停止，不降级到 dgekt 或 mock |
| 映射缺失 | 拒绝本次推理；保存缺口，不生成新的成功 TeachingState |
| 推理失败 | 已确认的判题和作答事实仍保存；本轮不生成新的成功 TeachingState |
| 归因不全 | 预测仍可用；attribution=partial |
| 重复已判分提交 | 不重复更新 mastery（保持现有幂等） |

## 12. 分阶段（只谈接入，不谈实验）

### Phase 1 — 契约

```text
定 TeachingState schema
Compiler 先吃现有 diagnosis + attribution
工具 / Package / facts 改读投影
补 model_version、confidence 占位
```

### Phase 2 — 接 SAFKT 引擎

```text
新增 safkt_engine，正式 factory 只创建 safkt
对齐：概率、薄弱点、遗忘、注意力→归因
映射进教学 content id
```

### Phase 3 — 教学真用上

```text
TeachingPlanner 读取 TeachingState 事实决定提示层级
PracticePathPlanner 结合 forgetting signal 和真实练习间隔决定练习路径
错因结合 attribution + 判分 + RAG
```

### Phase 4 — 对账

```text
state_id 全链路
变更版本与过期标记
专家侧按 fingerprint 可回看
```
