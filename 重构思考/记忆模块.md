# 记忆模块

这份文档记录 MathTutor Agent 记忆系统的重构目标设计。

它和另外几份文档的关系：

```text
系统总设计：页面模块怎么分、状态怎么同步。
思考链路：一次事件进来后怎么路由、调工具、写 Trace。
记忆模块：学生画像怎么分层、怎么提纯、怎么按需进上下文。
RAG模块：知识资源怎么检索、怎么带 citation。
上下文总设计：本轮回答时系统看见什么、怎么选、怎么裁、给谁用。
```

## 一句话目标

```text
记忆是「学生级内部画像」：跨对话框慢慢提纯重点，只影响怎么教，不改会不会；
每次只取最相关的几条，不全塞上下文。
```

## 产品定位

产品主心智仍是「当前题目 + 侧边 Agent 辅导」，不是纯聊天机器人。

记忆服务的是教学问题：

```text
怎么讲：提示多深、要不要先补概念、要不要举例子
怎么推：下一题难度、是否同一知识点、是否换讲法
怎么回：复盘时有依据地说「你最近在通分上反复卡」
```

不服务：

```text
改会不会（那是 KT / 判题 / progress）
当聊天 log 存档
闲聊个性人设
```

## 核心原则

### 1. 记忆跟人，不跟对话框

```text
一个学生 = 一个 Agent 画像
多开几个对话框 → 对话记录分开
               → 个人重点记忆共用同一份
```

用户感觉是：Agent 一直认识我。  
实现上是：共享学生级重点记忆，不共享整本聊天史。

### 2. 只记重点，不全记

```text
仓库可以稍多（后台存、可合并、可过期）
本轮只带最相关的一小包
```

宁缺毋滥：不相关、太旧、只出现一次、置信度低 → 不进上下文。

### 3. 聊天是原料，记忆是浓缩

不是每句话都写，也不是把对话全文落库。  
更像：教学相关对话结束后，后台扫一眼有没有新的、够稳的信号，再合并进画像。

### 4. 记忆影响策略，不改 mastery

```text
KT facts are authoritative.
Memory can influence strategy, not mastery.
RAG can support explanation, not overwrite prediction facts.
```

### 5. 记忆是内部能力

终局设计：

```text
用户不能手动新增、删除、禁用或编辑记忆。
系统只在后台根据学习行为和对话证据维护学生画像。
```

说明：当前代码里仍有学生端 enable / disable / delete 面板（V1.8）。  
重构目标按「内部画像」演进，与现状面板可解耦，不必在第一期硬删前端。

## 三类状态（必须拆开）

| 类型 | 跟谁 | 存什么 | 谁写 |
|------|------|--------|------|
| 学习事实状态 | 学生全局 | 题目、答案、判题、进度、当前题 | 交答案 / KT |
| 对话状态 | 某个 conversation | 这轮聊了啥、解释过什么 | 当前对话框 |
| 内部画像记忆 | 学生全局 | 偏好、稳定错因、有效策略、反思 | 后台提纯 |

```text
学习事实状态：全局共享
对话状态：属于某个 conversation，可引用当前学习事实
内部画像记忆：系统维护，跨对话框共用，用户终局不直接操作
```

## 分层架构

借鉴 ProbeFlow（分层 + 提纯 + 按需上下文）、Claude Code（短索引 / 细节按需读）、Codex（跨会话浓缩偏好），以及本仓库 `docs/V1_ARCHITECTURE.md` 中的 Memory Refinery 映射。

```text
教学对话 / 作答现场
        │
        ├─ Session Memory：当前对话框短窗口
        ├─ Task / 学习事实：当前题、作答状态、进度
        │
        ▼ 有证据、值得留时
LearningMemoryRefinery（提纯：抽 → 分 → 去重 → 合并 → 压缩）
        │
        ▼
学生级长期重点记忆（跨对话框）
        │
        ▼ 本轮回答前
按意图取 Top 3～5 + 当前题 + 最近几轮对话
        │
        ▼
Context 预算裁剪 → 生成回复
```

### Session Memory

```text
定位：当前对话框的短期现场
生命周期：单次对话 / 短 TTL
内容：最近几轮学生输入、AI 完整回复及关键结论
特点：强时效，不要求长期保留
```

### Task / 学习事实层

```text
定位：当前题与学习进度事实
内容：current question、作答记录、判题结果、KT 相关进度
特点：结构化、可恢复；不是画像，是账本
```

说明：MathTutor 的「任务」在教学场景里主要是「当前题 / 当前学习回合」，对应总设计里的学习事实状态，不必照搬 ProbeFlow 的测试 Task 模型。

### LearningMemoryRefinery（提纯层）

```text
职责：读取完整交互，判断哪些信息值得沉淀成长期重点
流程：extract → classify → deduplicate → merge → compress
触发：教学相关回合后异步执行，不阻塞主回复
节流：可排队合并、置信度门槛、低价值直接丢弃
```

适合提纯：

```text
学生多次表达的讲法偏好
同一知识点上反复出现的错因模式
AI 使用过且被后续反馈或作答验证有效的讲解 / 练习策略
学生明确表达且对后续教学有用的节奏或目标
```

不适合提纯：

```text
闲聊全文
单次偶发说法
整段解题对话原文
临时中间推理
已能从 KT / 题库直接推出的信息
```

### 学生级长期重点记忆

跨对话框仍有价值的浓缩条目。

建议类型：

```text
preference            讲法 / 题型 / 难度偏好
repeated_mistake      稳定错因模式
effective_strategy    有效教学或练习策略
reflection            学习节奏、目标、自我认知摘要
```

每条建议至少包含：

```text
memory_type
content / summary
evidence（question_id / concept_id / 来源事件等）
provenance（trace / session / 时间）
freshness / confidence
updated_at
```

边界：

```text
RAG：稳定知识（概念、解析、错因模式文档、策略文档）
Memory：个人经验（偏好、重复错因、策略效果、反思）
KT / progress：结构化会不会（mastery、weak concepts、prediction）
```

## 写路径

每轮交互要区分三类证据：

```text
学生证据：学生原话、正式作答、查看答案、换题反馈
AI 行为：AI 完整回复、用过的提示、解释、引用和推荐
结果证据：回复后的作答结果、换题行为、学生后续反馈
```

长期记忆的生成规则：

```text
学生偏好主要依据学生证据。
反复错因必须依据真实作答，不能依据 AI 对学生的描述。
AI 回复可以记录“系统讲过什么”，避免重复讲解。
有效教学策略必须同时有 AI 行为和后续结果证据，不能只因 AI 使用过就判定有效。
```

目标写路径：

```text
教学对话 / 学习行为
-> 保存学生输入 + AI 完整回复 + 本轮使用证据
-> Session 短记录 + 学习事实更新
-> 候选信号进入 Refinery
-> 判断是否值得长期保存
-> 去重合并后写入学生级记忆
-> 主交互记录保存学生输入、AI 完整回复和本轮事实
-> 异步记忆完成后另存关联的 memory_update 记录
```

与交答案的分工：

```text
交答案
-> 只保存作答事实 / 可选确定性判题 / 更新当前题状态
-> 不触发 Agent 对话
-> 默认不写画像；若后续要弱提纯，也只能基于已保存事实异步做

Agent 教学对话
-> 按需读画像
-> 完整 AI 回复写入本轮交互记录
-> 聊完后，有稳定教学信号再异步更新画像
```

不要做成：

```text
答对/答错就自动刷一条模板记忆
每句话都调用重型记忆写入
把整段聊天原文写进长期库
```

## 读路径

目标读路径：

```text
识别意图
-> 判断本轮是否需要 Memory
-> 需要时按 student_id + 当前题/概念/意图检索
-> 取 Top 3～5 重点
-> 与当前题状态、最近对话、可选 KT/RAG 组装
-> Context Governance 裁剪
-> 进入回复 / 推荐 / 讲解
```

### 按意图决定是否读

| 场景 | 是否读 Memory |
|------|----------------|
| 无关闲聊 | 否 |
| 交答案 | 否 |
| 当前题卡住 / 要提示 | 是（相关错因 + 讲法偏好） |
| 问为什么推荐这题 | 可选 |
| 问下一步做什么 | 可选（偏好难度/类型） |
| 学习总结 / 复盘 | 是 |
| 泛化概念问答 | 通常否，优先 RAG |

### 本轮上下文预算（人话版）

```text
最近对话 3～5 轮（当前对话框）
个人重点记忆 Top 3～5 条（与当前题/意图相关）
当前题 + 作答状态（必要事实）
需要时再加 KT / RAG
```

硬规则：

```text
闲聊：不带记忆
无关记忆：不带
stale / 低置信度：优先排除
无可用记忆：记 evidence gap，不伪造
```

## 多对话框行为示例

```text
对话框 A：分数题卡住，聊通分
  -> 后台强化「通分易错」这条学生级记忆

对话框 B（新建）：问「下一步练什么」
  -> 仍读同一学生画像
  -> 能用上 A 里攒下的通分易错
  -> B 的上下文没有 A 的全部聊天记录
  -> 只有浓缩重点 + B 自己的最近几句
```

## 参考来源与吸收边界

### 本仓库架构文档

```text
ProbeFlow Memory Refinery -> LearningMemoryRefinery
Mem0 风格记忆提纯 + Student Memory Store
接口方向：add / search / refine_from_session
```

### ProbeFlow

吸收：

```text
分层：Session / Task / Long-term
写：先提纯再写
读：Unified Context，TopK，不全塞
异步 Refinery、去重合并、淘汰
```

不照搬：测试领域的 case / 断言 / 鉴权经验内容。

### Claude Code

吸收：

```text
重点索引短、细节按需读

同「身份单元」共享记忆（项目 → 映射为学生）
```

不照搬：以 Markdown 文件为主存储；本项目长期记忆走 store / 可选 Mem0。

### Codex

吸收：

```text
跨会话记住浓缩偏好、坑点、习惯
不是每个对话框全文进记忆
```

### DeepTutor

吸收 Runtime / Capability / Trace 思想。  
明确不吸收：文件式记忆作主存储；规则 mastery 替代 KT。

## 现状与目标差距

| 维度 | 现状 | 目标 |
|------|------|------|
| 写入 | 答题对/错写模板句 | 教学对话后提纯再写 |
| 结构 | 基本一层 StudentMemoryStore | Session + 学习事实 + 长期画像 + Refinery |
| 读取 | 几乎每轮 search | 按意图按需 TopK |
| 身份 | 有 student_id | 明确多对话框共用学生画像 |
| 控制 | 学生可 enable/disable/delete | 终局偏内部维护 |
| 类型 | 四类模型已有，reflection 少写 | 教学重点完整维护与合并 |
| Runtime | 多为事后 memory observation | 真实调用链中的 search / refine 节点 |

已有基础可复用：

```text
StudentMemory 领域模型
Store 协议与 local / fake / Mem0 分层
Memory 不改 KT 的边界与测试
Context 层对 disabled/deleted 的排除
TeachingTrace 中的 memory 相关记录能力
```

## 建议接口形态

```text
StudentMemoryStore
  search(student_id, query, filters, top_k)
  write(memory)                 # 或 upsert by dedupe key
  list_recent(student_id, limit)
  get(student_id, memory_id)

LearningMemoryRefinery
  refine_from_turn(student_id, student_input, assistant_response, turn_trace, learning_facts) -> memory_updates
  # 异步、可节流、可空结果
```

Policy guard：

```text
提交答案本身不触发 agent，也不应默认写画像
没有教学证据 -> 不写长期记忆
内部画像无可用证据 -> 不纳入上下文
Memory 结果不能覆盖 mastery / prediction / weak concepts
AI 回复只能证明“系统说过或做过什么”，不能单独证明学生事实或策略有效
```

## 与思考链路的衔接

写在主链路末尾：

```text
Observe -> Route -> Retrieve -> Diagnose -> Assemble -> Act -> 保存完整交互 -> 异步 Reflect/Memory
```

对应意图策略：

```text
off_topic_chat              不读不写 Memory
answer_submission           不读；只存事实；默认不写画像
stuck_on_current_problem    可读 Memory；聊后可提纯
recommendation_explanation  可选读
next_step_request           可选读
review_summary              要读；可写 reflection
```

## 一句话总结

```text
一个学生 = 一个 Agent；
多对话框 = 多现场，同一套重点记忆；
聊天 = 原料，记忆 = 浓缩后的教学重点；
上下文 = 短现场 + 几条重点，绝不整本历史；
记忆只服务怎么教，不改会不会。
```
