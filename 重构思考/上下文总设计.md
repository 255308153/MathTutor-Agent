# 上下文总设计

这份文档说明：Agent **每一轮回答时，到底该看见什么**。

和其它文档的分工：

```text
系统总设计 → 页面和状态怎么分
思考链路   → 一次请求怎么路由、调工具
记忆模块   → 学生画像怎么记、怎么提纯
RAG模块    → 资料怎么检索
本文       → 本轮把哪些信息装进「小包」给教学用
```

---

## 1. 是什么

**上下文 = 这一轮教学生时，系统允许看见的一小包信息。**

```text
按学生现在想干嘛，只装相关的几样
装不下就丢掉次要的
没有就说「缺什么」，不许瞎编
只影响「怎么教」，绝不改「会不会」
```

产品仍是「当前题目 + 侧边辅导」，不是纯聊天机器人。

**管什么**

```text
怎么讲、怎么推下一题、怎么有依据地复盘
```

**不管什么**

```text
改掌握度 / 存整本聊天 / 当闲聊人设
```

---

## 2. 几条硬规矩

1. **不全塞**  
   历史可以很多，本轮只带最相关的一小包。

2. **会不会 vs 怎么教**  
   - 会不会：只听判题、进度、KT  
   - 怎么教：记忆、资料、讲解策略可以帮忙  
   - 上下文不能改掌握度

3. **先看意图，再取资料**  
   不要每轮都固定查记忆 + RAG + KT。

4. **缺了就明说**  
   没有记忆、没有解析 → 记「缺口」，不编引用、不编偏好。

5. **真正选题时分两步组装，但都走同一个上下文模块**
   点击「下一题」后，选题前组装“选题资料包”；选题后加入选中题解析，组装“回答资料包”。聊天里问下一步只给方向建议，不进入这条选题链。调用方不要绕路读取原始接口。

---

## 3. 装什么：三类原料

| 原料 | 跟谁 | 是什么 | 本轮怎么带 |
|------|------|--------|------------|
| 学习事实 | 学生全局 | 当前题、作答、对错、进度、KT | 只带本轮相关部分；相关 KT 事实不能被其它资料挤掉 |
| 对话现场 | 某一个对话框 | 最近聊了啥 | 只带最近 3～5 轮，不要全文 |
| 内部画像 | 学生全局 | 偏好、常错点、有效讲法等 | 只带最相关的 3～5 条 |

```text
一个学生 = 一份画像（多对话框共用）
一个对话框 = 自己的短现场（不把别的对话框全文带过来）
```

---

## 4. 怎么装：简单流程

```text
学生说一句话
    ↓
判断他想干嘛（闲聊 / 卡住 / 下一步 / 交答案 …）
    ↓
只去取「这一轮需要」的东西（可并行查）
    ↓
排个序，装进本轮需要的资料包
    ↓
用这包决定怎么讲 / 推什么
    ↓
记下来：带了啥、扔了啥、缺了啥
```

**谁先谁后（重要的先留）**

```text
1. 与当前题或目标知识点相关的 KT 结论——有就必留
2. 当前题和作答情况
3. 本轮相关的工具结果摘要
4. 相关记忆
5. 相关资料（RAG）
6. 其它审计用的引用 —— 最先可扔
```

**本轮大概带多少（人话）**

```text
最近对话几句
记忆几条
当前题（有就带）
需要时再加 KT、再加几条资料
```

**两条特别规定**

```text
交答案
  → 保存作答事实 / 判题结果
  → 更新 KT 并编译 TeachingState
  → 不查资料、不查记忆、不组回答资料包、不自动推荐

问下一步练什么（聊天）
  → 读取 TeachingState、近期作答和当前对话短现场
  → 只解释适合的学习方向，不调用推荐器，不切换当前题
  → 不组装选题资料包，也不查题目解析

点「下一题」（页面动作）
  → 先组装选题资料包，再诊断、选题
  → 再查「选中那道题」的解析
  → 组装回答资料包
  → 不要还没选题就乱查一堆题解
```

## 5. 不同情况装什么

先认准场景，再决定开不开工具。

| 学生在干嘛 | 带什么 | 别带 / 别做 |
|------------|--------|-------------|
| 闲聊 | 几乎空，必要时拉回学习 | KT、资料、记忆、改进度 |
| 问泛化概念 | 可选资料 | 一般不调 KT、不绑当前题 |
| 当前题卡住 | 当前题 + 可选记忆 + 可选本题解析 | 一般不改掌握度 |
| 交答案 | **不组回答资料包** | 仍保存作答事实、判题结果并更新 KT；不查资料/记忆、不推荐、不讲解 |
| 问下一步练什么 | TeachingState、近期作答、当前对话短现场；必要时带相关记忆 | 不调用推荐器、不查题解、不切换当前题 |
| 点「下一题」 | 选题资料包：TeachingState、近期作答、换题反馈、题库摘要；选题后再带当前题解析 | 不把它当聊天，不带整段历史对话 |
| 问为什么推荐这题 | 当时的推荐理由 + 当前题 | 不必重新推一题 |
| 复盘总结 | 进度、近期作答、可选记忆/KT | 不许编历史 |

代码里如果暂时只有 3 类意图，可以先这样对应；但点击「下一题」必须新增独立的系统事件，不能继续借用聊天意图：

```text
answer_submission         → 提交答案，只更新事实和 KT
next_step_advice          → 聊天里问下一步，只给方向建议
general_chat              → 闲聊 / 概念 / 卡住 / 为什么推荐（靠路由再细分）
next_question_requested   → 点击下一题，新增系统事件，执行选题和切题
```

## 6. 装好之后长什么样

同一个上下文模块只在真正需要选题或回答时工作，分两个阶段：

```text
点「下一题」
    ↓
选题资料包：TeachingState、近期作答、最近换题反馈、相关偏好、题库摘要
    ↓ 推荐器选出当前题
回答资料包：选题资料包 + 当前题 + 当前题解析和引用

问下一步练什么不会进入上面这条选题链，只生成一段方向建议。
```

**给回复的那一包里应有**

```text
本轮意图
与本轮相关的 KT 权威结论（有则）
当前题情况（有则）
选中的记忆摘要
选中的资料（带引用）
缺了什么（缺口列表）
```

**绝对不要进这一包**

```text
密钥、原始接口大包、向量全文、调试日志
已删除的记忆、没选中的证据
```

学生只看正常讲解；  
「带了啥 / 裁了啥」给专家调试面板看即可。

细节实现继续使用同一个 `LearningContextLayer`；两个资料包是同一模块的阶段性输出，**不是两套平行对象**。

## 7. 和记忆、资料的关系

上下文**不负责**「怎么记记忆、怎么建索引」，只负责**本轮读哪些、装多少**。

```text
记忆：按需搜几条相关的；写画像放在回复后后台做（见记忆模块）
资料：按题号/知识点过滤，防串题；空结果就记缺口（见 RAG 模块）
KT：只读结论，进「权威」位置，不能被记忆或资料改掉
```

```text

让模型或规则直接改掌握度
每轮全工具全检索再靠模型自己挑
```

## 9. 和现状差在哪（先改这些）

| 现在容易怎样 | 目标 |
|--------------|------|
| 很多轮一进来就固定拉记忆+资料 | 先看意图，需要再拉 |
| 交答案也走一整套教学组装 | 交答案只更新事实和 KT，不组回答资料包 |
| 对话短现场不明显 | 本对话框只带最近几轮 |
| 推荐前就查一堆解析 | 选题后再查该题 |
| 组装结果有了，决策还可能绕路读原始列表 | 决策只读「给回复的那一包」 |

**已经有、别推倒**

```text
LearningContextLayer、预算裁剪、证据缺口、KT 权威边界、Trace 审计
```

**建议落地顺序（由易到难）**

```text
1. 按场景规定「装什么」（先覆盖：闲聊 / 卡住 / 下一步建议 / 点击下一题 / 交答案）
2. 交答案不再组回答资料包
3. 补上对话短窗口
4. 规划/回复只读组装后的包
5. 推荐链路改成「点击下一题后组装选题包，选题后再查解析」
```

---

## 10. 怎样算做对了

```text
交答案 → 没有教学用的记忆/资料大包
闲聊   → 没有一堆 KT/资料
卡住   → 能看见当前题；没题就说明缺题
记忆/资料改不了 KT 结论
没资料 → 有缺口记录，没有假引用
装不下 → 有裁掉原因，KT 和当前题核心还在
```

---

## 一句话

```text
按场景装一小包：当前题和 KT 优先，记忆和资料按需，
能裁能记缺口，只教不改分。
```
