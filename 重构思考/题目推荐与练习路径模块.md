# 题目推荐与练习路径模块设计

这份文档说明 MathTutor Agent 里“下一题推荐”和“练习路径”应该怎么设计。

核心目标不是做一个看起来很复杂的推荐算法，而是让系统像一个会看错题本的老师：

```text
先判断学生现在为什么需要练；
再决定下一步应该怎么练；
最后才从题库里选一道合适的题。
```

---

## 1. 模块一句话定义

```text
题目推荐与练习路径模块负责根据学生当前学习状态，
决定下一步练习节奏，并选出可解释、可追溯的下一题。
```

更通俗一点：

```text
它不是简单“挑一道分数最高的题”，
而是先判断学生该补弱点、巩固、复习还是进阶。
```

---

## 2. 为什么要拆成“路径”和“推荐”

如果只有 Recommender，很容易变成：

```text
输入一堆候选题
-> 每道题打分
-> 返回最高分
```

这样能推荐题，但解释不清楚“为什么现在练这个”。

真正的教学场景里，老师一般会先判断：

```text
学生刚做错，要不要先纠错？
学生刚做对，要不要巩固？
连续做对了，要不要升难度？
某个知识点很久没练，要不要复习？
某个知识点反复错，要不要进入专项练习？
```

所以这里建议拆成两个模块：

```text
PracticePathPlanner：决定下一步练习路径和节奏。
RiskPrioritizedRecommender：按路径目标从题库里选题。
```

一句话：

```text
练习路径模块负责“怎么练”；
推荐器负责“选哪题”。
```

---

## 3. 整体链路

推荐下一题时，建议走这条链路：

```text
学习事件
-> KT / TeachingState 诊断学生状态
-> PracticePathPlanner 决定练习路径
-> 按路径约束初筛候选题
-> CandidateKTScorer 批量计算候选题的 SAFKT 目标题概率
-> Recommender 按路径目标筛题和排序
-> 保存 current_question / recommendation_history
-> 写入 TeachingTrace
```

这里要注意：

```text
提交答案不一定等于推荐下一题。
如果产品上希望提交后自动给下一题，可以显式走 recommend_after_answer。
如果产品上希望提交和推荐分离，就只在“下一题按钮”触发路径规划。
```

这个边界必须在代码里显式表达，不能靠 LLM 猜。

---

## 4. PracticePathPlanner 做什么

PracticePathPlanner 是这个模块的核心。

它不直接管题库，也不负责算每道题分数。

它只回答一个问题：

```text
学生下一步应该走哪种练习路径？
```

第一版可以支持这些路径类型。

### 4.1 纠错路径

触发条件：

```text
刚提交答案
并且判定为错误
```

路径目标：

```text
先处理刚才错因。
优先推荐同知识点、难度略低或相近、解析完整的题。
```

学生侧解释：

```text
刚才这道题涉及这个知识点，下一题先用相近题型继续检查；只有直接错因证据充分时，才说明具体错在哪里。
```

### 4.2 巩固路径

触发条件：

```text
刚提交答案
并且判定为正确
但相关知识点掌握度还没有很稳定
```

路径目标：

```text
继续练同知识点或同类型题，难度保持相近。
```

学生侧解释：

```text
你这题做对了，但这个知识点还需要再巩固一题。
```

### 4.3 进阶路径

触发条件：

```text
同一知识点近期连续做对
掌握度较高
遗忘风险较低
```

路径目标：

```text
推荐稍高难度的变式题或综合题。
```

学生侧解释：

```text
基础题已经比较稳了，下一步试一道稍有变化的题。
```

### 4.4 复习路径

触发条件：

```text
某个知识点的遗忘信号较高
并且真实记录显示已经较久没有练习
```

路径目标：

```text
穿插一道复习题，难度不要太高。
```

学生侧解释：

```text
这个知识点隔了一段时间没练，先用一题快速唤醒。
```

### 4.5 专项练习路径

触发条件：

```text
同一知识点或同一错因反复出现
```

路径目标：

```text
连续安排 2-3 道同知识点变式题。
先低难度纠错，再相近难度巩固，最后小幅进阶。
```

学生侧解释：

```text
这个错误出现了不止一次，接下来用一个小练习组集中处理。
```

### 4.6 冷启动路径

触发条件：

```text
没有足够学习历史
没有明确薄弱知识点
```

路径目标：

```text
选内容完整、难度适中、覆盖基础知识点的题。
```

学生侧解释：

```text
先从一题基础题开始，我会根据你的作答继续调整。
```

## 5. 输入需要什么

PracticePathPlanner 不应该直接读取一堆原始日志。

它应该接收已经整理好的学习事实。

第一版输入可以是：

```text
student_id
session_id
current_event
current_question
answer_result
concept_states（支持多个知识点）
weak_concepts
forgetting_risks
recent_events
recommendation_history
review_queue
student_preferences
context_evidence_gaps
```

其中最重要的是：

```text
是否刚答错
是否刚答对
当前知识点掌握度
遗忘信号与真实练习间隔
最近是否重复推荐
错题队列
题目内容是否完整
```

---

## 6. 输出需要什么

PracticePathPlanner 输出的不是题目，而是路径决策。

建议结构：

```text
PracticePathDecision
  path_type
  target_concept_ids[]
  primary_concept_id
  primary_concept_name
  target_teaching_type
  difficulty_policy
  candidate_constraints
  review_policy
  reason
  student_message
  evidence
```

示例：

```json
{
  "path_type": "mistake_repair",
  "target_concept_ids": ["c_fraction_addition"],
  "primary_concept_id": "c_fraction_addition",
  "primary_concept_name": "异分母分数加法",
  "target_teaching_type": "procedure",
  "difficulty_policy": "same_or_slightly_easier",
  "candidate_constraints": {
    "concept_ids": ["c_fraction_addition"],
    "max_recent_repeat": 0,
    "requires_complete_explanation": true
  },
  "reason": "刚才答错，错因集中在通分步骤。",
  "student_message": "下一题先练同知识点的相近题，把通分步骤练稳。",
  "evidence": {
    "last_question_id": "q_frac_001",
    "is_correct": false,
    "mistake_patterns": ["没有通分"]
  }
}
```

## 7. Recommender 怎么配合

Recommender 接收 PracticePathDecision 后，再去题库里选题。

它负责：

```text
按目标知识点筛题
按难度策略筛题
排除近期重复题
优先选择内容完整题
优先选择 XES3G5M / KC routes 对齐完整的题
结合学生偏好排序
返回候选题和分数原因
```

候选题需要使用 SAFKT 预测风险时，Recommender 不直接调用模型。系统先按路径约束
完成初筛，再由 `CandidateKTScorer` 批量计算各候选题的目标题概率，最后把结果作为
只读评分字段交给 Recommender。

推荐分数可以保留这些因子：

```text
目标知识点匹配
难度适配
遗忘风险
预测风险
近期重复度
内容完整度
XES3G5M / KC routes 对齐
学生偏好
上下文支持度
```

注意：

```text
如果某个因子会出现在推荐解释里，就应该真的参与排序；
如果不参与排序，就不要把它包装成打分因子。
```

这样可以避免“解释说参考了上下文，但排序其实没用上下文”的问题。

## 8. 状态怎么保存

推荐不是一次性文本，必须保存证据。

建议在学习进度里保留：

```text
current_question
当前页面展示、等待学生作答的题。

recommendation_history
最近推荐过哪些题、路径类型、分数、原因。

review_queue
错题或高遗忘风险知识点的复习队列。

practice_path_state
如果进入专项练习，记录当前小路径进度。
```

`recommendation_history` 不应该只存题号和分数。

至少要存：

```text
question_id
path_type
target_concept_ids
primary_concept_id
score
reason
decision_evidence
created_at
```

这样学生问“为什么推荐这题”时，系统读取当时的推荐证据即可，不需要重新猜。

## 9. 和其他模块的关系

### 9.1 和 KT / TeachingState 的关系

KT / TeachingState 负责判断：

```text
学生会不会
哪里薄弱
是否存在遗忘信号，以及真实练习间隔是否支持该判断
最近哪些历史记录重要
```

PracticePathPlanner 负责使用这些事实：

```text
根据学习事实决定下一步练习路径。
```

它不能反过来修改 mastery 或 prediction。

### 9.2 和 RAG 的关系

RAG 不负责决定学生会不会，也不负责直接选题。

RAG 主要用于：

```text
给推荐题提供解析、错因、概念解释和 citation。
```

推荐链路里，RAG 可以放在选题之后：

```text
先选题
再查选中题对应的解释和错因文档
```

这样能减少串题和无关引用。

### 9.3 和 Memory 的关系

Memory 可以影响策略，但不能改写学习事实。

例如：

```text
学生偏好步骤拆解
学生经常在通分上犯错
学生更适合先看 worked example
```

这些可以影响：

```text
教学动作
推荐理由
题目难度节奏
```

但不能直接改变：

```text
mastery
prediction_probability
weak_concepts
forgetting_risks
```

### 9.4 和回复流程的关系

PracticePathPlanner 决定：

```text
下一步练什么路径。
```

学生主动提问后，回复流程根据当前问题读取题目、判题、TeachingState、RAG 和 Memory，直接生成对应回复。

例如：

```text
PracticePathPlanner：进入纠错路径，练异分母分数加法。
回复流程：学生询问怎么做时，再读取题解并生成对应提示。
```

## 10. 简单流程示例

### 10.1 答错后的推荐

学生提交：

```text
题目：1/2 + 1/4
答案：1/6
判题：错误
错因：分母直接相加，没有通分
```

系统流程：

```text
KT 更新异分母分数加法掌握度
TeachingState 标记该知识点薄弱
PracticePathPlanner 选择 mistake_repair
Recommender 选择同知识点、难度略低或相近的题
回复流程根据学生的问题生成错因解释或步骤提示
Trace 记录为什么这么推荐
```

学生看到：

```text
你刚才错在“异分母分数加法”的通分步骤。
下一题先练一道同知识点的相近题，把通分动作练稳。
```

### 10.2 连续做对后的推荐

学生最近连续做对同知识点基础题。

系统流程：

```text
PracticePathPlanner 选择 advancement
Recommender 提高目标难度
回复流程根据学生的问题生成进阶题说明或解题提示
```

学生看到：

```text
这个知识点的基础题已经比较稳了。
下一步试一道稍有变化的题，看看能不能迁移使用。
```

### 10.3 遗忘风险触发复习

某知识点很久没有练，并且遗忘信号升高。

系统流程：

```text
PracticePathPlanner 选择 review
Recommender 选择低中难度复习题
回复流程根据学生的问题生成快速复习说明
```

学生看到：

```text
这个知识点隔了一段时间没练，先用一题快速唤醒。
```

## 11. 第一版实现建议

不要一开始做复杂路径图。

第一版只做一个规则型 PracticePathPlanner：

```text
if 刚答错:
    mistake_repair
elif 当前知识点遗忘信号高且真实练习间隔较长:
    review
elif 刚答对但掌握度不高:
    consolidation
elif 最近连续做对:
    advancement
elif 同一错因反复出现:
    focused_practice
else:
    cold_start
```

然后让 Recommender 根据 path decision 调整筛选和排序。

这已经足够支撑：

```text
错题纠错
巩固练习
复习穿插
难度递进
推荐理由可解释
```

## 12. 后续优化方向

后续可以逐步加：

```text
1. practice_path_state：支持 2-3 题小练习组。
2. prerequisite graph：支持前置知识点补漏。
3. spaced repetition：更明确的间隔复习调度。
4. difficulty calibration：根据真实正确率校准题目难度。
5. exploration / exploitation：少量探索新题型，避免推荐过窄。
6. 路径效果评估：看推荐后下一题是否做对，反向评估路径策略。
```

这些都可以后加。

第一版最重要的是先把职责分清：

```text
KT 判断学习事实。
PracticePathPlanner 决定练习节奏。
Recommender 选择具体题目。
回复流程根据学生主动提出的问题生成回复。
TeachingTrace 记录为什么这么做。
```

---

## 13. 一句话总结

```text
题目推荐不是直接挑题，而是先判断学生此刻需要哪种练习路径。
路径决定练习节奏，推荐器负责从题库中选出最合适的下一题。
```
